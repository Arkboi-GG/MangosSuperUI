# zulgurub_trash

## Purpose & Responsibilities

`zulgurub_trash.cpp` implements the artificial intelligence (AI) scripts for several non-boss ("trash") creatures found within the Zul'Gurub instance in World of Warcraft. This unit defines distinct AI behaviors for five specific creature types: **Gurubashi Axe Thrower**, **Gurubashi Berserker**, **Hakkari Doctor**, **Esprit Vaudou** (Voodoo Spirit), **Fils Hakkar** (Son of Hakkar), and **Jinxed Voodoo Pile**.

The primary responsibility of this unit is to manage combat timers, spell casting logic, target selection, and special event triggers (such as death or low health) for these entities. It relies heavily on the `ScriptedAI` base class framework provided by the server core. Notably, while the code defines AI for all six creature types listed above, the registration function `AddSC_zg_trash` only actively registers four of them (`npc_gurubashi_berserker`, `npc_hakkari_doctor`, `npc_esprit_vaudou`, and `npc_jinxed_voodoo_pile`). The scripts for `npc_gurubashi_axethrower` and `npc_fils_hakkar` are commented out during registration, meaning their AI will not load unless the registration block is modified.

This unit does not interact with any database tables; all logic is driven by in-memory state, timers, and game object interactions.

## Member-by-Member Behavior

### Gurubashi Axe Thrower
This AI controls a ranged/melee hybrid attacker that uses thrown axes and melee flurries.

*   **GurubashiAxeThrowerAI**: The constructor initializes the AI, retrieves the instance data via `WorldObject.Object/GetInstanceData`, and calls `Reset`.
*   **Reset**: Initializes two timers: `m_uiThrow_Timer` (5 seconds) and `m_uiAxeFlurry_Timer` (10 seconds). It also sets the enrage flag `m_bEnrage` to false.
*   **Aggro**: Called when the creature enters combat. It marks the creature as being in combat with the zone using `Creature.Main/SetInCombatWithZone`.
*   **UpdateAI**: The main loop.
    *   It checks for a valid hostile target.
    *   **Axe Flurry**: If the timer expires and the creature is not disarmed (`UNIT_FLAG_DISARMED`), it casts `SPELL_AXE_FLURRY` (ID 24018) on the victim. The timer resets to a random value between 14–19 seconds.
    *   **Throw**: If the throw timer expires, it casts `SPELL_THROW` (ID 16075) on the victim. The timer resets to a random value between 4–7 seconds.
    *   **Enrage**: If health drops below 50% and the creature hasn't already enraged, it casts `SPELL_FRENZY` (ID 8269) on itself and sets the enrage flag to true.
    *   Finally, it attempts a melee attack if ready.
*   **GetAI_GurubashiAxeThrower**: Factory function returning a new instance of the AI.

### Gurubashi Berserker
This AI controls a melee-focused berserker that uses crowd control and knockback abilities.

*   **GurubashiBerserkerAI**: Constructor initializes the AI, retrieves instance data, and calls `Reset`.
*   **Reset**: Initializes three timers: `m_uiKnockBack_Timer` (10s), `m_uiThunderClap_Timer` (5s), and `m_uiFear_Timer` (15s). Sets `m_bEnrage` to false.
*   **Aggro**: Marks the creature as in combat with the zone.
*   **UpdateAI**: The main loop.
    *   **Knockback**: If the timer expires, it casts `SPELL_KNOCKBACK` (ID 11130) on the victim. Crucially, after casting, it calls `ScriptedAI/DoResetThreat` to reset threat generated by the knockback, preventing aggro loss issues. Timer resets to 10 seconds.
    *   **Thunder Clap**: If the timer expires, it casts `SPELL_THUNDERCLAP` (ID 15588) on the victim. Timer resets to a random value between 14–16 seconds.
    *   **Fear**: If the timer expires, it casts `SPELL_FEAR` (ID 16508) on the victim. Like Knockback, it calls `ScriptedAI/DoResetThreat` afterwards. Timer resets to a random value between 25–30 seconds.
    *   **Enrage**: If health drops below 50% and not already enraged, it casts `SPELL_ENRAGE` (ID 8269) on itself and sets the enrage flag.
    *   Finally, it attempts a melee attack if ready.
*   **GetAI_GurubashiBerserker**: Factory function returning a new instance of the AI.

### Hakkari Doctor
This AI controls a caster that summons minions and uses targeted spells. Upon death, it spawns a Voodoo Spirit.

*   **npc_hakkari_doctor**: Constructor initializes the AI, retrieves instance data, and calls `Reset`.
*   **Reset**: Initializes four timers: `m_uiMaleficeTimer` (5s), `m_uiCrapaudsTimer` (15s), `m_uiCrapaudsLiberationTimer` (15s), and `m_uiOrionOmbreTimer` (4s).
*   **UpdateAI**: The main loop.
    *   **Malefice**: If the timer expires, it finds the farthest victim within 10–20 yards using `Creature.Main/GetFarthestVictimInRange`. If found, it casts spell ID 24053 on them. Timer resets to a random value between 20–40 seconds.
    *   **Crapauds (Toads)**: If the timer expires, it finds the farthest victim within 10–20 yards. It then summons 4 creatures (ID 15010) near that target using `Unit.Main/SummonCreatureAndAttack`. Timer resets to a random value between 10–40 seconds.
    *   **Crapauds Liberation**: If the timer expires, it searches for a nearby summoned toad (ID 15010) within 40 yards using `WorldObject.Object/FindNearestCreature`. If found, it casts spell ID 24065 on the toad and makes it disappear and die (`Creature.Main/DisappearAndDie`). Timer resets to 1 second.
    *   **Orion Ombre (Shadow Orb)**: If the timer expires, it finds the farthest victim within 10–20 yards and casts spell ID 17289 on them. Timer resets to a random value between 5–20 seconds.
    *   Finally, it attempts a melee attack if ready.
*   **JustDied**: When the doctor dies, it summons a Voodoo Spirit (ID 15009) targeting the killer using `Unit.Main/SummonCreatureAndAttack`.
*   **GetAI_npc_hakkari_doctor**: Factory function returning a new instance of the AI.

### Esprit Vaudou (Voodoo Spirit)
This AI controls a summoned spirit that moves toward its target and explodes upon contact.

*   **npc_esprit_vaudou**: Constructor sets the creature flags to `UNIT_FLAG_SPAWNING` and `UNIT_FLAG_NOT_SELECTABLE`, making it initially invisible/unselectable. It then calls `Reset`.
*   **Reset**: Empty implementation.
*   **UpdateAI**: The main loop.
    *   It retrieves the current victim.
    *   If the distance to the victim is less than 5 yards (`WorldObject.Object/GetDistance#3`), it casts spell ID 24050 (Spiritual Explosion) on the victim.
    *   Immediately after casting, it adds itself to the removal list (`WorldObject.Object/AddObjectToRemoveList`) to despawn.
*   **GetAI_npc_esprit_vaudou**: Factory function returning a new instance of the AI.

### Fils Hakkar (Son of Hakkar)
This AI controls a melee attacker with knockdown and self-buff capabilities. Note: Its registration is commented out in `AddSC_zg_trash`.

*   **npc_fils_hakkar**: Constructor calls `Reset`.
*   **Reset**: Initializes two timers: `m_uiKnockDownTimer` (10s) and `m_uiTrashTimer` (5s).
*   **UpdateAI**: The main loop.
    *   **Trash (Buff?)**: If the timer expires, it casts spell ID 3391 on itself. Timer resets to a random value between 20–40 seconds.
    *   **Knock Down**: If the timer expires, it casts spell ID 16790 on the victim. Timer resets to a random value between 5–10 seconds.
    *   Finally, it attempts a melee attack if ready.
*   **JustDied**: When the creature dies, it casts spell ID 24320 on itself.
*   **GetAI_npc_fils_hakkar**: Factory function returning a new instance of the AI.

### Jinxed Voodoo Pile
This AI controls an object that mind-controls a player and then kills itself. Note: Its registration is active.

*   **npc_jinxed_voodoo_pileAI**: Constructor calls `Reset`.
*   **Reset**: Sets `m_castedMindControl` to false.
*   **UpdateAI**: The main loop.
    *   It first checks if the creature has a charm GUID (`Unit.Main/GetCharmGuid`). If it does (meaning it has successfully mind-controlled someone), it does nothing further in this check.
    *   If it has no charm GUID:
        *   If `m_castedMindControl` is true (spell was cast but charm hasn't applied yet?), it kills the creature using `Unit.Main/DoKillUnit`.
        *   If `m_castedMindControl` is false, it searches for the nearest player within 5 yards using `WorldObject.Object/FindNearestPlayer`.
        *   If a player is found, it casts `SPELL_WILL_OF_HAKKAR` (ID 24178) on them. If the cast succeeds, it sets `m_castedMindControl` to true and marks the creature as in combat with the zone (`Creature.Main/SetInCombatWithZone`).
*   **GetAI_npc_jinxed_voodoo_pile**: Factory function returning a new instance of the AI.

### Script Registration

*   **AddSC_zg_trash**: This function registers the AI scripts with the script manager.
    *   It creates `Script` objects for `npc_gurubashi_berserker`, `npc_hakkari_doctor`, `npc_esprit_vaudou`, and `npc_jinxed_voodoo_pile`.
    *   It links each script name to its corresponding `GetAI_*` factory function.
    *   It calls `ScriptMgr/RegisterSelf` for each.
    *   **Important**: The registration blocks for `npc_gurubashi_axethrower` and `npc_fils_hakkar` are commented out. Consequently, these creatures will not use the custom AI defined in this file unless the comments are removed.

## Cross-Unit Boundaries

*   **ScriptedAI**: All AI structs inherit from `ScriptedAI`. They use methods like `DoCastSpellIfCan`, `DoMeleeAttackIfReady`, and `DoResetThreat` from this base class to handle standard combat mechanics.
*   **WorldObject.Object**: Used for retrieving instance data (`GetInstanceData`), setting flags (`SetFlag`), finding nearby entities (`FindNearestCreature`, `FindNearestPlayer`), calculating distances (`GetDistance#3`), and managing object lifecycle (`AddObjectToRemoveList`).
*   **Creature.Main / Unit.Main**: Used for combat state management (`SetInCombatWithZone`, `DoKillUnit`), target selection (`SelectHostileTarget`, `GetVictim`, `GetFarthestVictimInRange`), summoning (`SummonCreatureAndAttack`), and spell casting (`CastSpell#2`).
*   **shared_Util**: Uses `urand` for generating random timer intervals.
*   **SpellCaster**: Uses `CastSpell#2` for direct spell casting operations.
*   **ScriptMgr**: `AddSC_zg_trash` calls `RegisterSelf` on `Script` objects to integrate the AIs into the server's script system.

## Data Model

This unit does not access any database tables. All state is maintained in memory via member variables in the AI structs.

## Notable Implementation Details

1.  **Commented Out Registrations**: The `AddSC_zg_trash` function explicitly comments out the registration for `npc_gurubashi_axethrower` and `npc_fils_hakkar`. While the AI classes for these creatures are fully implemented in the source, they will not be loaded by the server unless this code is uncommented. This suggests these scripts might be incomplete, deprecated, or intended for future use.
2.  **Threat Reset Logic**: In `GurubashiBerserkerAI::UpdateAI`, the `DoResetThreat()` call is made immediately after casting `SPELL_KNOCKBACK` and `SPELL_FEAR`. This is a critical detail to prevent the berserker from losing aggro due to the high damage or crowd-control nature of these spells, ensuring it remains the primary target.
3.  **Voodoo Spirit Lifecycle**: The `npc_esprit_vaudou` AI is designed to be short-lived. It starts with spawning/not-selectable flags. Once it reaches its target (within 5 yards), it explodes and immediately queues itself for deletion. This prevents lingering entities.
4.  **Doctor's Minion Management**: The `npc_hakkari_doctor` summons toads (ID 15010) and has a separate timer (`m_uiCrapaudsLiberationTimer`) to find and kill them. This ensures that summoned minions do not persist indefinitely if the doctor is kept alive for a long time, or perhaps to trigger a specific visual effect (spell 24065) before their death.
5.  **Jinxed Voodoo Pile Self-Kill**: The `npc_jinxed_voodoo_pileAI` has a unique flow. It casts a mind-control spell (`SPELL_WILL_OF_HAKKAR`). If the spell cast succeeds, it sets a flag. On the next update, if it still doesn't have a charm GUID (perhaps the spell failed to apply or took time), it kills itself. This prevents the pile from endlessly attempting to cast or existing after a failed attempt.
6.  **Hardcoded Spell IDs**: Many spell IDs are hardcoded in enums or directly in the code (e.g., `24053`, `15010`). This ties the logic tightly to specific database entries. Changes to these IDs in the database would break the AI behavior.
