# Log.Main

## Purpose & Responsibilities

The `Log` class serves as the central, singleton-based logging infrastructure for the MaNGOS server application. It manages the routing, formatting, filtering, and output of diagnostic, operational, and error messages generated throughout the server lifecycle.

Its primary responsibilities include:
1.  **Multi-destination Output:** Writing logs to the console (stdout/stderr), multiple specialized log files (e.g., `Chat.log`, `Bg.log`, `DBErrors.log`), and potentially the database (via level checks, though the actual DB write logic resides in callers like `DatabaseMysql`).
2.  **Hierarchical Filtering:** Enforcing severity levels (`ERROR`, `MINIMAL`, `BASIC`, `DETAIL`, `DEBUG`) independently for console, file, and database outputs.
3.  **Feature-Specific Filtering:** Allowing administrators to enable or disable verbose logging for specific subsystems (e.g., AI movement, spell casting, combat calculations) via bitmask filters.
4.  **Smart Logging:** Providing a mechanism to selectively increase logging verbosity for specific entities (identified by Entry ID or GUID) to aid in debugging particular creatures or objects without flooding the logs with global data.
5.  **Console Formatting:** Applying ANSI escape codes (Unix) or Windows Console API attributes to color-code log messages by severity for easier visual parsing in terminal windows.
6.  **Initialization Coordination:** Parsing configuration settings to open log files, set directories, and initialize smart-log lists during server startup.

## Member-by-Member Behavior

### Initialization and Configuration

**`Log()`**
The constructor initializes the singleton instance. It performs the following steps:
1.  Initializes internal state variables (`m_includeTime`, `m_logsTimestamp`, `m_defaultColor`).
2.  Sets all `logFiles` pointers to `nullptr`.
3.  Reads the `LogsDir` configuration setting. If specified, it ensures the directory path ends with a separator (`/` or `\`).
4.  Opens the basic log file (`LogFile.Basic`) using `OpenLogFile`.
5.  Reads boolean flags for `Warden.DebugLog` and `LogTime`.
6.  Reads integer values for `LogLevel.Console`, `LogLevel.File`, and `LogLevel.DB`, casting them to `LogLevel` enums.
7.  Parses string configurations `Smartlog.ExtraEntries` and `Smartlog.ExtraGuids` into unordered sets via `InitSmartlogEntries` and `InitSmartlogGuids`.
8.  Iterates through the `logFilterData` array, checking corresponding boolean config keys (e.g., `LogFilter_TransportMoves`) to build the `m_logFilter` bitmask.

**`~Log()`**
The destructor iterates through the `logFiles` array and closes any open `FILE*` handles using `fclose`, preventing resource leaks upon server shutdown.

**`OpenWorldLogFiles()`**
Called after initial configuration to open secondary log files. It reads the `LogFile.TimeStamp` config to determine if filenames should be timestamped. It opens files for Chat, Battlegrounds, Characters, Honor, Realm Accounts, DB Errors, DB Error Fixes, Loots, Level Ups, Performance, Money Trades, GM Commands, GM Critical Commands, Anticheat, Scripts, Movement, and Network.
*   Note: `LOG_GM` is only opened if `GmLogPerAccount` is true.
*   Note: `LOG_HONOR` and `LOG_MONEY_TRADES` use empty default filenames, meaning they rely entirely on explicit config keys to be enabled; otherwise, they remain `nullptr`.

**`InitSmartlogEntries(std::string const& str)`**
Parses a space-separated string of unsigned integers (Entry IDs) and populates `m_smartlogExtraEntries`. This allows targeted logging for specific creature templates.

**`InitSmartlogGuids(std::string const& str)`**
Parses a space-separated string of unsigned integers (GUIDs) and populates `m_smartlogExtraGuids`. This allows targeted logging for specific spawned instances of creatures/objects.

### Log Level Management

**`GetConsoleLevel()`**, **`GetFileLevel()`**, **`GetDbLevel()`**
Simple accessor methods returning the current severity threshold for console, file, and database logging respectively. These are queried by commands like `HandleServerLogLevelCommand` in `ChatHandler.ServerCommands` and checks like `IsPlayerLoggingEnabledToDB` in `Player.Main`.

**`SetConsoleLevel(LogLevel level)`**
Updates `m_consoleLevel`. It clamps the value between `LOG_LVL_ERROR` and `LOG_LVL_DEBUG`. It prints confirmation to stdout.

**`SetFileLevel(LogLevel level)`**
Updates `m_fileLevel`. It casts the `LogLevel` enum to `int32` via `atoi` (a slightly unusual pattern, likely due to legacy interface constraints), clamps it, and updates the member. It prints confirmation to stdout.

### Filter Management

**`HasLogFilter(uint32 filter)`**
Returns `true` if the bit corresponding to the provided `LogFilters` enum value is set in `m_logFilter`. This is heavily used across the codebase (e.g., `Creature.Main`, `Spell.Main`, `Map.Main`) to gate verbose debug output. If the filter is active, the caller typically *skips* the log message (see macro definitions in `Log.h`), implying these filters act as "exclude verbose noise" switches rather than "include only these" switches in many contexts, although the naming suggests inclusion. The macros `DETAIL_FILTER_LOG` and `DEBUG_FILTER_LOG` confirm this: they log *if* the level is high enough AND the filter is *not* active.

**`SetLogFilter(LogFilters filter, bool on)`**
Sets or clears the bit in `m_logFilter` corresponding to the provided filter. Used by `HandleServerLogFilterCommand` in `ChatHandler.ServerCommands`.

**`HasLogLevelOrHigher(LogLevel loglvl)`**
Returns `true` if either the console level or the file level (provided a basic log file is open) meets or exceeds the requested severity. This is a common guard clause used before constructing expensive log strings.

### Output Formatting and Helpers

**`GetConsoleColor()`**
A static helper (defined in the anonymous namespace in `Log.cpp`) that captures the initial console text color on Windows using `GetConsoleScreenBufferInfo`. On non-Windows platforms, it returns 0. This value is stored in `m_defaultColor` to allow resetting colors later.

**`SetColor(FILE* where, Color color)`**
Applies a specific color to the output stream.
*   **Windows:** Uses `SetConsoleTextAttribute` with pre-defined `WORD` constants mapping `Color` enums to `FOREGROUND_*` flags.
*   **Unix/Linux:** Uses `fprintf` to write ANSI escape sequences (`\x1b[...m`). It distinguishes between normal and bold/intense colors for the upper half of the `Color` enum.

**`ResetColor(FILE* where)`**
Resets the console color to the default captured at startup.
*   **Windows:** Restores `m_defaultColor` via `SetConsoleTextAttribute`.
*   **Unix/Linux:** Writes an ANSI reset sequence.

**`OutTimestamp(FILE* file)`**
Writes a full timestamp (`YYYY-MM-DD HH:MM:SS`) to the specified file handle.

**`OutTime(FILE* where)`**
Writes a short timestamp (`HH:MM:SS`) to the specified file handle.

**`GetTimestampStr()`**
Generates a string formatted as `_YYYY-MM-DD_HH-MM-SS`. This is used primarily for appending timestamps to log filenames during initialization.

**`IsIncludeTime()`**
Returns whether the `LogTime` config option was enabled, controlling whether short timestamps are prepended to console output.

**`IsSmartLog(uint32 entry, uint32 guid)`**
Checks if the given entry ID or GUID exists in the smart-log sets. Used by `Creature.Main/LogDeath` to determine if extra death information should be logged.

### Core Logging Functions

**`Out(LogType logType, LogLevel logLevel, char const* format, ...)`**
The primary variadic logging function.
1.  Validates `logType` and `logLevel`.
2.  Performs a quick check: if both console and file levels are below the required level, it returns immediately.
3.  Expands `va_list` arguments.
4.  Invokes `LOG_TO_CONSOLE_HELPER`:
    *   Skips `LOG_PERFORMANCE` and `LOG_DBERRFIX` for console output.
    *   Selects `stderr` for errors, `stdout` otherwise.
    *   Applies color via `SetColor`.
    *   Prepends time if `m_includeTime` is true.
    *   Prepends "ERROR: " if level is error.
    *   Prints the formatted string using `vutf8printf` (from `shared_Util`).
    *   Resets color and flushes.
    *   If the log type is not `LOG_BASIC`, it also writes the same message to the basic log file via `LOG_TO_FILE_HELPER` embedded within the macro.
5.  Invokes `LOG_TO_FILE_HELPER`:
    *   Checks if the specific log file for `logType` is open and the file level permits it.
    *   Skips timestamp for `LOG_DBERRFIX`.
    *   Prepends timestamp and "ERROR: " prefix as needed.
    *   Writes the formatted string and flushes.

**`OutConsole(LogType logType, LogLevel logLevel, std::string const& log)`**
Logs a pre-formatted string to the console.
1.  Skips `LOG_PERFORMANCE` and `LOG_DBERRFIX`.
2.  Checks console level.
3.  Applies color, time, and error prefix similar to `Out`.
4.  Uses `utf8printf` (from `shared_Util`) to print the string.
5.  If the log type is not `LOG_BASIC`, it delegates to `OutFile` to write to the basic log file, ensuring consistency between console view and main log file.

**`OutFile(LogType logType, LogLevel logLevel, std::string const& str)`**
Logs a pre-formatted string to a specific log file.
1.  Checks if the file handle exists and the file level permits it.
2.  Prepends timestamp (unless `LOG_DBERRFIX`) and error prefix.
3.  Writes the string and flushes.

### Utility and Startup Control

**`OpenLogFile(char const* configFileName, char const* defaultFileName, bool timestampFile, bool overwriteOnOpen)`**
Opens a log file based on configuration.
1.  Retrieves the filename from config, falling back to `defaultFileName`.
2.  If the filename is empty, returns `nullptr`.
3.  Determines the file mode:
    *   `"w"` (truncate) if `timestampFile` is true or `overwriteOnOpen` is true.
    *   `"a"` (append) otherwise.
4.  If `timestampFile` is true, it inserts the `m_logsTimestamp` string before the file extension (or appends it if no extension exists).
5.  Prepends `m_logsDir` and opens the file using `fopen`.

**`WaitBeforeContinueIfNeed()`**
Pauses server startup based on the `WaitAtStartupError` config integer.
*   If negative: Waits for user input (Enter key) via `std::getline`.
*   If positive: Sleeps for the specified number of seconds, displaying a progress bar via `ProgressBar/BarGoLink` and `ProgressBar/step`.
*   If zero: Continues immediately.
This is called by various initialization routines (e.g., `DatabaseMysql/DatabaseMysql`, `World/LoadConfigSettings`) to allow administrators to inspect early crash logs or errors before the server proceeds.

## Cross-Unit Boundaries

The `Log` unit acts as a passive sink for almost all other units in the system. It is rarely a caller itself, except for configuration retrieval and utility functions.

*   **Config Integration:**
    *   Calls `Config/GetBoolDefault`, `Config/GetIntDefault`, and `Config/GetStringDefault` during construction and file opening to read logging preferences.
*   **Utility Integration:**
    *   Calls `shared_Util/vutf8printf` and `shared_Util/utf8printf` for Unicode-safe string formatting in console output.
    *   Calls `ProgressBar/BarGoLink` and `ProgressBar/step` in `WaitBeforeContinueIfNeed` to visualize startup delays.
*   **Caller Diversity:**
    *   **Core Systems:** `WorldSocket`, `DatabaseMysql`, `Map.Main`, `Player.Main`, `Unit.Main` all frequently call `Out`, `OutConsole`, or check `HasLogLevelOrHigher`/`HasLogFilter` to emit status updates, errors, and debug traces.
    *   **Game Logic:** `Spell.Main`, `Creature.Main`, `GameObject/Use` use logging for combat, spell effects, and object interactions.
    *   **Administration:** `ChatHandler.ServerCommands` uses `SetConsoleLevel`, `SetFileLevel`, `SetLogFilter`, and the getters to allow runtime adjustment of logging behavior.
    *   **Specialized Modules:** `AiBotAI` modules, `Warden` (anti-cheat, implemented in `Log.Warden`), and `BattleGround` managers all route their diagnostic output through `Log`.

## Data Model

The `Log` unit interacts with the database indirectly through its design, but the specific member `OpenWorldLogFiles` references the table `realmd_Main/main` in the MAP. However, examining the source code for `OpenWorldLogFiles` reveals **no SQL queries**. The reference in the MAP likely indicates that the *configuration* for these logs might be stored in the `realmd` database, or it is a residual artifact. The `Log` class itself does not execute queries against `realmd_Main/main`.

The `Log` class writes to the filesystem (log files) and standard I/O streams. It does not directly insert rows into any database table. Database logging is handled by other units (e.g., `DatabaseMysql`) which may call `Log::Out` or check `Log::GetDbLevel`, but the actual SQL execution is outside this unit.

## Notable Implementation Details

1.  **Singleton Pattern:** `Log` inherits from `MaNGOS::Singleton<Log, ...>`, ensuring a single global instance accessible via `sLog`. This simplifies logging calls across the codebase but requires careful initialization order (handled by the constructor calling Config).
2.  **Platform-Specific Console Colors:** The code explicitly handles Windows vs. Unix differences for console coloring. Windows uses `SetConsoleTextAttribute`, while Unix uses ANSI escape codes. The `GetConsoleColor` function captures the initial Windows console state to allow proper restoration.
3.  **Filter Logic Inversion:** The `HasLogFilter` method checks if a filter is *active*. However, the macros `DETAIL_FILTER_LOG` and `DEBUG_FILTER_LOG` in `Log.h` use `!sLog.HasLogFilter(F)`. This means enabling a filter (setting it to true) *disables* the detailed/debug logging for that category. This is a critical gotcha for administrators: enabling `LogFilter_AIAndMovegens` will *suppress* AI debug logs, not enable them.
4.  **Smart Logging:** The `IsSmartLog` method allows granular debugging. By adding specific Entry IDs or GUIDs to the config, developers can trigger extra logging (e.g., in `Creature.Main/LogDeath`) only for those entities, reducing noise.
5.  **File Mode Handling:** `OpenLogFile` supports both appending and overwriting. Timestamped files always overwrite (`"w"`), while non-timestamped files append (`"a"`) unless `overwriteOnOpen` is true. This prevents log files from growing indefinitely if timestamps are used, but risks losing history if timestamps are disabled and the server restarts frequently with overwrite mode.
6.  **UTF-8 Support:** The use of `vutf8printf` and `utf8printf` indicates support for UTF-8 encoded log messages, important for internationalization in chat and NPC text logs.
7.  **Performance Logging Exclusion:** `LOG_PERFORMANCE` and `LOG_DBERRFIX` are explicitly excluded from console output in `Out` and `OutConsole`. This prevents performance metrics and raw SQL fix scripts from cluttering the administrator's terminal.
8.  **Basic Log Mirroring:** When a non-basic log type (e.g., `LOG_CHAT`) is written to the console, `OutConsole` automatically mirrors it to the basic log file (`LOG_BASIC`). This ensures the main server log contains a consolidated view of console-visible events.

## Member Reference

**GetConsoleColor**: Static helper function (anonymous namespace) that retrieves the initial console text color on Windows using `GetConsoleScreenBufferInfo`; returns 0 on non-Windows platforms. Used to store the default color for later restoration.

**Log**: Constructor that initializes the singleton. It reads configuration for log directory, file names, severity levels (console, file, DB), and smart-log entries/GUIDs. It opens the basic log file and initializes the log filter bitmask based on config booleans.

**OpenWorldLogFiles**: Method that opens secondary log files (Chat, BG, Char, etc.) based on configuration. It determines file modes (append vs. overwrite) and applies timestamps if configured. It conditionally opens the GM log based on `GmLogPerAccount`.

**InitSmartlogEntries**: Method that parses a space-separated string of Entry IDs from configuration and populates the `m_smartlogExtraEntries` unordered set for targeted logging.

**InitSmartlogGuids**: Method that parses a space-separated string of GUIDs from configuration and populates the `m_smartlogExtraGuids` unordered set for targeted logging.

**SetColor**: Method that applies a specific color to a `FILE*` stream. On Windows, it uses `SetConsoleTextAttribute`; on Unix, it writes ANSI escape codes. It maps `Color` enums to platform-specific attributes.

**~Log**: Destructor that iterates through the `logFiles` array and closes any open `FILE*` handles using `fclose` to prevent resource leaks.

**GetConsoleLevel**: Accessor method returning the current severity threshold for console logging.

**GetFileLevel**: Accessor method returning the current severity threshold for file logging.

**GetDbLevel**: Accessor method returning the current severity threshold for database logging.

**HasLogFilter**: Method that checks if a specific log filter bit is set in `m_logFilter`. Returns `true` if the filter is active. Note: Active filters often suppress debug output in macros.

**SetLogFilter**: Method that sets or clears a specific log filter bit in `m_logFilter` based on the `on` boolean parameter.

**HasLogLevelOrHigher**: Method that returns `true` if either the console level or the file level (if a basic log file is open) meets or exceeds the specified severity level. Used as a guard clause before logging.

**IsIncludeTime**: Accessor method returning whether timestamps are included in console output, based on the `LogTime` config setting.

**ResetColor**: Method that resets the console color to the default captured at startup. On Windows, it restores `m_defaultColor`; on Unix, it writes an ANSI reset sequence.

**SetConsoleLevel**: Method that updates the console log level, clamping the value between `LOG_LVL_ERROR` and `LOG_LVL_DEBUG`, and prints a confirmation message.

**SetFileLevel**: Method that updates the file log level, clamping the value, and prints a confirmation message. It casts the `LogLevel` enum to `int32` via `atoi`.

**OpenLogFile**: Helper method that opens a log file based on configuration. It handles filename resolution, timestamp insertion, and file mode selection (append vs. overwrite). Returns a `FILE*` or `nullptr` if the filename is empty.

**OutTimestamp**: Static method that writes a full timestamp (`YYYY-MM-DD HH:MM:SS`) to a specified `FILE*`.

**OutTime**: Static method that writes a short timestamp (`HH:MM:SS`) to a specified `FILE*`.

**GetTimestampStr**: Static method that generates a timestamp string formatted as `_YYYY-MM-DD_HH-MM-SS`, used for filename generation.

**Out**: Primary variadic logging function. It validates inputs, checks severity levels, and dispatches output to console and/or files using helper macros. It handles color coding, timestamping, and error prefixes. It mirrors non-basic console logs to the basic log file.

**OutConsole**: Method that logs a pre-formatted string to the console. It applies color, time, and error prefixes. It mirrors non-basic logs to the basic log file via `OutFile`.

**OutFile**: Method that logs a pre-formatted string to a specific log file. It applies timestamps (except for `LOG_DBERRFIX`) and error prefixes, then flushes the file.

**IsSmartLog**: Method that checks if a given Entry ID or GUID is present in the smart-log sets, enabling targeted verbose logging for specific entities.

**WaitBeforeContinueIfNeed**: Method that pauses server startup based on the `WaitAtStartupError` config. It waits for user input (if negative) or sleeps for a specified duration with a progress bar (if positive).
