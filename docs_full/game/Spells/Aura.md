# Aura System: `SpellAuraHolder` and `Aura`

## Purpose & Responsibilities

The `SpellAuras.h` unit defines the core data structures and interface for the **Aura** system in the WoWVMaNGOS engine. An "Aura" represents the persistent effect of a spell on a target (e.g., a buff like *Bloodlust* or a debuff like *Polymorph*).

This unit is responsible for:
1.  **State Management:** Tracking the lifecycle of spell effects, including duration, stacking, charges, and application/removal states.
2.  **Effect Application:** Providing a dispatch mechanism (`Handle...` methods) to apply specific game mechanics (stat modifications, immunity, movement changes, etc.) when an aura is added or removed.
3.  **Hierarchy:** Distinguishing between the **Holder** (`SpellAuraHolder`), which manages the aggregate state of a single spell instance on a target (stacks, duration, caster info), and the **Aura** (`Aura`), which represents individual effects within that spell (since one spell can have multiple effects, e.g., Damage over Time + Stat Buff).
4.  **Integration Hooks:** Exposing data to other systems (Combat, AI, UI, Persistence) via getters for modifiers, spell prototypes, and caster/target identities.

There are **no database tables** directly touched by this unit. Persistence is handled by `Player` and `Pet` units calling `SetLoadedState` and `SaveAura`/`LoadAura` methods, which serialize/deserialize the fields defined here.

## Member-by-Member Behavior

### `SpellAuraHolder`: The Spell Instance Container

`SpellAuraHolder` acts as the container for all effects generated by a single cast of a spell on a specific target. It manages the "meta-data" of the spell effect.

#### Lifecycle and State
*   **`SetLoadedState`**: Initializes the holder's state from saved data (caster GUID, item GUID, stacks, charges, duration). Called by `Player.Main/LoadAura` and `Pet.Main/_LoadAuras`.
*   **`SetStackAmount` / `GetStackAmount`**: Manages the stack count of the aura. Stacking is crucial for buffs/debuffs that increase in potency with repeated applications.
*   **`DropAuraCharge` / `SetAuraCharges`**: Manages consumable charges. `DropAuraCharge` returns `true` if the last charge was consumed, signaling potential removal.
*   **`SetRemoveMode` / `GetRemoveMode`**: Tracks *why* an aura was removed (e.g., expired, dispelled, killed). Used by `Unit.Main/RemoveAura` and various scripts (`boss_grobbulus`, `spell_mage`) to determine post-removal behavior.
*   **`SetInUse` / `IsInUse`**: A reentrancy guard. Increments a counter when the aura is being processed (e.g., during `Update` or `ApplyModifier`). Prevents recursive deletion or modification loops. Called by `Unit.AuraProcHandler` and `Unit.SpellAuras`.
*   **`SetDeleted` / `IsDeleted`**: Marks the holder for cleanup. Checked by `Unit.Main/CleanupDeletedAuras`.

#### Identity and Relationships
*   **`GetCasterGuid` / `GetRealCasterGuid` / `GetCastItemGuid`**: Returns the GUIDs of the entity that cast the spell, the "real" caster (important for channeled spells or pets acting on behalf of owners), and the item used. These are heavily queried by `Unit.Main` (for damage calculations, immunity checks) and `Unit.SpellAuras` (for applying effects).
*   **`GetCaster` / `GetRealCaster`**: Resolves the GUIDs to actual `Unit` or `SpellCaster` objects. Used by `Unit.SpellAuras` handlers (e.g., `HandleAuraModAttackPower`) to fetch caster stats for dynamic calculations.
*   **`GetTarget`**: Returns the unit affected by the aura. Used extensively by `Unit.SpellAuras` handlers to apply effects to the correct entity.
*   **`GetSpellProto`**: Returns the `SpellEntry` (DBC data) for the spell. Used by almost every subsystem to determine spell properties (school, rank, mechanics).

#### Duration and Timing
*   **`GetAuraMaxDuration` / `GetAuraDuration`**: Returns the total possible duration and the remaining time. Used by `ChatHandler` for debugging and `Unit.SpellAuras/Update` for expiration logic.
*   **`SetAuraDuration` / `SetAuraMaxDuration`**: Updates timing. `Refresh` logic often adjusts these.
*   **`RefreshAuraPeriodicTimers`**: Resets timers for periodic effects. Called by `Unit.SpellAuras/Refresh`.

#### Exclusivity and Priority
*   **`IsExclusive` / `CheckExclusiveWith` / `ComputeExclusive`**: Implements the "exclusive aura" logic (e.g., only one major haste buff can be active). `CheckExclusiveWith` compares two holders to determine which persists. Called by `Unit.SpellAuras/ApplyModifier` and `Unit.Main/GetMostImportantAuraAfter`.
*   **`IsMoreImportantVisualAuraThan`**: Determines which aura icon takes precedence in the UI when slot limits are reached.

#### Modification Application
*   **`ApplyAuraModifiers`**: The central dispatcher that iterates through all `Aura` objects in the holder and calls their respective `Handle...` methods. Called by `Unit.Main/AddAuraToModList` and `Unit.SpellAuras/Refresh`.
*   **`HandleSpellSpecificBoosts`**: Applies special boosts associated with the spell type.

### `Aura`: The Individual Effect

`Aura` represents a single effect line from the spell definition. It contains the logic for *what* happens when the effect is applied or removed.

#### Handlers (The "What")
The `Aura` class contains dozens of `Handle...` methods. Each corresponds to an `AuraType` from the DBC. These methods are called by `ApplyModifier` (via function pointers or switch statements in the implementation, though declared here).
*   **Stat Mods**: `HandleAuraModStat`, `HandleAuraModAttackPower`, `HandleModCritPercent`, etc. These adjust the target's combat stats.
*   **Immunities**: `HandleAuraModSchoolImmunity`, `HandleModMechanicImmunity`. These grant resistance to damage types or crowd control.
*   **Movement**: `HandleAuraModIncreaseSpeed`, `HandleAuraModRoot`, `HandleAuraHover`.
*   **Periodic Effects**: `HandlePeriodicDamage`, `HandlePeriodicHeal`. These trigger damage/healing over time.
*   **Special Mechanics**: `HandleAuraDummy` (generic hook for scripts), `HandleAuraTransform` (morphing), `HandleModCharm` (control).

*Note: Many of these are declared but implemented in `SpellAuras.cpp` (not provided here). Their presence in the header defines the contract.*

#### Core Logic Methods
*   **`GetModifier`**: Returns the `Modifier` struct containing the effect type (`m_auraname`), amount (`m_amount`), and misc value (`m_miscvalue`). This is the primary data source for `Unit.Main/GetTotalAuraModifier` and similar aggregation functions.
*   **`ApplyModifier`**: The entry point for applying or removing the effect. It checks exclusivity (`ComputeExclusive`) and then calls the appropriate `Handle...` method. Called by `Unit.SpellAuras/ApplyModifier`.
*   **`Update` / `UpdateAura`**: Handles time-based progression. Decrements duration, triggers periodic ticks (`PeriodicTick`), and checks for expiration. Called by `Unit.SpellAuras/Update`.
*   **`PeriodicTick`**: Executes the logic for periodic effects (DoT/HoT). Calculates damage/healing amounts and applies them. Called by `Update`.
*   **`TriggerSpell`**: If the aura is configured to trigger another spell (e.g., *Flamestrike* triggering *Fire Shield*), this method initiates that cast. Called by `Unit.SpellAuras/TriggerSpell`.

#### State Flags
*   **`IsPositive` / `SetPositive`**: Indicates if the aura is a buff (positive) or debuff (negative). Affects UI and debuff limit logic.
*   **`IsPersistent`**: Indicates if the aura survives death or logout.
*   **`IsAreaAura`**: Indicates if the aura affects an area (handled by `AreaAura` subclass).
*   **`IsChanneled`**: Indicates if the aura is tied to a channeled spell (broken if channel breaks).

#### Subclasses
*   **`AreaAura`**: Extends `Aura` to handle radius-based effects. Overrides `Update` to manage affected targets within the radius.
*   **`PersistentAreaAura`**: Extends `Aura` for world-persistent effects (e.g., *Consecration* on the ground). Linked to a `DynamicObject`.
*   **`SingleEnemyTargetAura`**: Extends `Aura` for effects that track a specific enemy target (e.g., *Curse of Agony* targeting the highest threat).

## Cross-Unit Boundaries

### Called By: `Unit.Main`
*   **Collaboration**: `Unit.Main` is the primary consumer of Aura data for combat calculations.
*   **Direction**: `Unit.Main` -> `Aura`/`SpellAuraHolder`.
*   **Why**: To calculate total modifiers (damage, healing, resistances), check immunities, and manage aura lists (add/remove).
*   **Key Calls**: `GetModifier`, `GetSpellProto`, `GetCasterGuid`, `IsImmuneToSchoolMask`, `RemoveAura`.

### Called By: `Unit.SpellAuras`
*   **Collaboration**: `Unit.SpellAuras` contains the implementation logic for applying and updating auras.
*   **Direction**: `Unit.SpellAuras` -> `Aura`/`SpellAuraHolder`.
*   **Why**: To execute the actual game logic defined in the `Handle...` methods and manage the lifecycle (update, refresh, exclusive checks).
*   **Key Calls**: `ApplyModifier`, `Update`, `Refresh`, `ComputeExclusive`, `TriggerSpell`.

### Called By: `Player.Main` / `Pet.Main`
*   **Collaboration**: Persistence and initialization.
*   **Direction**: `Player`/`Pet` -> `SpellAuraHolder`.
*   **Why**: To save/load aura states from the database and initialize auras on login/spawn.
*   **Key Calls**: `SetLoadedState`, `SaveAura`, `LoadAura`.

### Called By: `SpellCaster` / `Spell.Main`
*   **Collaboration**: Spell casting and resolution.
*   **Direction**: `Spell` -> `Aura`/`SpellAuraHolder`.
*   **Why**: To create new auras upon successful cast, resolve targets, and handle spell-specific aura interactions.
*   **Key Calls**: `CreateAura`, `GetSpellProto`, `GetCaster`.

### Called By: `ChatHandler`
*   **Collaboration**: Debugging and admin commands.
*   **Direction**: `ChatHandler` -> `Aura`/`SpellAuraHolder`.
*   **Why**: To display aura information to players/admins.
*   **Key Calls**: `GetModifier`, `GetAuraMaxDuration`, `GetStackAmount`.

## Data Model

This unit does **not** directly interact with database tables. It operates entirely in memory.

However, it relies on the following implicit data structures for persistence, managed by `Player` and `Pet` units:
*   **`character_aura`** (or similar): Stores `caster_guid`, `item_guid`, `stack_amount`, `charges`, `max_duration`, `duration`. These fields map directly to `SpellAuraHolder::SetLoadedState`.

## Notable Implementation Details

1.  **Reentrancy Guard (`m_in_use`)**:
    *   Both `Aura` and `SpellAuraHolder` use an `m_in_use` counter. This is critical because applying an aura might trigger another spell (via `TriggerSpell`), which might try to remove or modify the original aura. The counter prevents double-free or invalid state access during recursive updates.

2.  **Exclusive Aura Logic**:
    *   The `CheckExclusiveWith` method implements complex rules for determining which of two conflicting auras (e.g., two haste buffs) remains. This involves comparing spell ranks, levels, and specific flags. This logic is centralized in `SpellAuraHolder` but invoked by `Unit.SpellAuras`.

3.  **Modifier Struct**:
    *   The `Modifier` struct is a lightweight data carrier. It does not contain logic. All interpretation of `m_auraname` and `m_miscvalue` happens in the `Handle...` methods. This separation allows for efficient iteration over modifiers without executing heavy logic until necessary.

4.  **Periodic Tick Calculation**:
    *   `GetAuraMaxTicks` calculates the maximum number of ticks based on duration and periodic time. This is used to ensure periodic effects don't exceed their intended lifespan due to timer drift.

5.  **Nostalrius/Elysium Specifics**:
    *   Comments indicate specific patches for "Nostalrius" and "Elysium Project," such as `HandleAuraAuraSpell` and `HandleInterruptRegen`. These suggest custom mechanics or fixes specific to this fork's emulation goals.
