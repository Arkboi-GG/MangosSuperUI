# SpellTargetEntry

**Purpose & Responsibilities**

`SpellTargetEntry` is a lightweight data structure defined in `SpellMgr.h` that represents a single script-defined targeting constraint for a specific spell. It encapsulates the rules determining whether a spell can target a specific entity type (Creature, GameObject, Dead Unit, or Player) based on the entity's entry ID, optional conditions, and specific spell effects.

This structure is part of the `SpellMgr` system, which loads and manages static spell data at server startup. `SpellTargetEntry` instances are stored in a multimap (`SpellScriptTarget`) keyed by spell ID, allowing the engine to quickly look up all targeting restrictions for a given spell. Its primary responsibility is to provide a fast, bitwise check to determine if a specific spell effect is explicitly forbidden from hitting a target defined by this entry.

**Member-by-Member Behavior**

The unit consists of two members: a constructor and a query method.

*   **`SpellTargetEntry` (Constructor)**
    *   **Kind:** Constructor
    *   **Behavior:** Initializes the `SpellTargetEntry` instance with four parameters:
        1.  `type_`: The `SpellTargetType` (e.g., Creature, GameObject).
        2.  `targetEntry_`: The specific entry ID of the target (e.g., a creature entry or game object entry).
        3.  `conditionId_`: An optional condition ID that must be met for this targeting rule to apply.
        4.  `inverseEffectMask_`: A bitmask where each bit corresponds to a `SpellEffectIndex`. If a bit is set, it indicates that the corresponding spell effect *cannot* hit this target.
    *   **Implementation Detail:** The constructor uses an initializer list to assign these values directly to the struct's member variables. It does not perform validation or logging.

*   **`CanNotHitWithSpellEffect` (Method)**
    *   **Kind:** Method
    *   **Signature:** `bool CanNotHitWithSpellEffect(SpellEffectIndex effect) const`
    *   **Behavior:** Determines if a specific spell effect index is blocked by this targeting entry. It performs a bitwise AND operation between the `inverseEffectMask` and a mask generated by shifting `1` left by the `effect` index.
    *   **Return Value:** Returns `true` if the bit corresponding to `effect` is set in `inverseEffectMask`, meaning the spell effect is *not* allowed to hit the target defined by this entry. Returns `false` otherwise.
    *   **Logic:** `(inverseEffectMask & (1 << effect)) != 0`

**Notable Implementation Details**

1.  **Bitwise Masking for Efficiency:** The use of `inverseEffectMask` allows multiple spell effects to be blocked by a single entry efficiently. Instead of storing a list of blocked effects, a single integer acts as a compact set of flags. This enables O(1) checks for any effect index.
2.  **Inverse Logic:** The naming `CanNotHitWithSpellEffect` and `inverseEffectMask` indicates that the mask defines *exclusions*. If a bit is set, the effect is *blocked*. This is a crucial distinction for maintainers: adding a target entry with a mask blocks those effects; it does not enable them.
3.  **Const Correctness:** `CanNotHitWithSpellEffect` is marked `const`, ensuring it does not modify the state of the `SpellTargetEntry`. This allows it to be called on const references, which is important since the entries are stored in a `const` multimap iterator range during spell targeting checks.
4.  **Inline Definition:** Both the constructor and `CanNotHitWithSpellEffect` are defined inline within the struct definition in the header file. This suggests they are small, performance-critical functions that benefit from inlining to avoid call overhead during the frequent spell targeting checks.
5.  **No Validation:** The constructor does not validate the `effect` index passed to `CanNotHitWithSpellEffect`. If an invalid index (e.g., >= 32 for a 32-bit `uint32`) is passed, the behavior is undefined due to the left shift operation. However, `SpellEffectIndex` is likely constrained to valid ranges (0-2) by the rest of the codebase.
