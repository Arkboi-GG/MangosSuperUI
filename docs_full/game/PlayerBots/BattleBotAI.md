# BattleBotAI

`BattleBotAI` is the specialized artificial intelligence controller for SuperUiBots participating in World of Warcraft battlegrounds: Warsong Gulch (WSG), Arathi Basin (AB), and Alterac Valley (AV). Unlike general-purpose bot AIs, this class implements the unique lifecycle, objective-oriented movement, and class-specific combat rotations required for large-scale PvP environments, ensuring bots queue, enter, fight, and exit battlegrounds autonomously.

## How the class is split

The implementation is divided into two partials, separating high-level decision-making and lifecycle management from low-level navigation and map-specific pathing.

### BattleBotAI.Main
This partial contains the core AI logic, lifecycle hooks, and class-specific combat behaviors. It manages the bot’s entry into and exit from battlegrounds, handles death and resurrection, and orchestrates the main update loop (`UpdateAI`). It implements detailed spell rotations and decision trees for nine classes (Paladin, Shaman, Hunter, Mage, Priest, Warlock, Warrior, Rogue, Druid), tailoring behavior to battleground contexts such as flag carrier protection and defensive cooldown usage. It also handles utility tasks like mounting, eating/drinking, and target selection.

### BattleBotAI.BattleBotWaypoints
This partial implements the waypoint navigation system specific to WSG, AB, and AV. It defines static path data (coordinates and callback functions) for routes within these maps and provides the logic for bots to traverse these paths. It handles reactions to objectives (flags, banners, graveyards) and selects new destinations based on game state. Its primary responsibility is translating high-level strategic goals into low-level movement commands (`MovePoint`) while managing edge cases like dismounting, graveyard jumps, and combat interruptions.

## How the partials collaborate

`BattleBotAI.Main` acts as the driver, delegating navigation tasks to `BattleBotAI.BattleBotWaypoints`. The collaboration follows a clear request-response pattern:

1.  **Path Selection:** `BattleBotAI.Main.UpdateWaypointMovement` calls methods in `BattleBotAI.BattleBotWaypoints` (such as `StartNewPathToObjective`, `StartNewPathFromBeginning`, or `StartNewPathFromAnywhere`) to determine the next route based on the current battleground state and strategic priorities.
2.  **Execution:** Once a path is selected, `BattleBotAI.BattleBotWaypoints.MoveToNextPoint` drives the bot’s physical movement along the waypoints.
3.  **Callbacks:** When a waypoint is reached, `BattleBotAI.BattleBotWaypoints.MovementInform` executes any associated callback function (e.g., `WSG_AtAllianceFlag` or `AtFlag`). These callbacks may interact with game objects or trigger actions in `BattleBotAI.Main` (such as `DoGraveyardJump` or `UseMount`).
4.  **Interruption:** Combat or state changes detected by `BattleBotAI.Main` (e.g., `AttackStart`, `OnJustDied`) call `BattleBotAI.BattleBotWaypoints.ClearPath` to reset navigation state, allowing the AI to pivot to combat or survival behaviors.

Shared state flows primarily through the `Player` object and AI-specific member variables, with no direct database interaction. The class relies on `CombatBotBaseAI` for core combat utilities and `BattleGround` for map-specific state information.

## Data model

This class does not interact with any database tables. All path data, spell IDs, and configuration are hardcoded in C++ source files. Bot state is transient and stored in memory within the `Player` object and `BattleBotAI` member variables, meaning bot progress is lost upon server restart.
