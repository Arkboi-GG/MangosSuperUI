# WardenScan

## Purpose & Responsibilities

`WardenScan` defines the data structures and logic for **Warden anti-cheat scans** in the WoWVMaNGOS server. It provides a polymorphic hierarchy of `Scan` objects that represent specific integrity checks performed on the client. These scans are used to detect unauthorized modifications, injected modules, hooked APIs, or tampered memory/files on the player's machine.

The unit implements:
1.  **Base Scan Logic**: The `Scan` class abstracts the lifecycle of a scan: building the request packet sent to the client (`Build`) and validating the response packet received from the client (`Check`).
2.  **Platform-Specific Scans**: Distinct classes for Windows (`WindowsScan` derivatives) and Mac (`MacScan` derivatives), reflecting the different capabilities of the Warden/Maiev modules on each OS.
3.  **Specific Check Types**: Concrete implementations for common anti-cheat checks, including:
    *   String hashing (integrity verification of the Warden module itself).
    *   Module presence detection.
    *   Memory content verification.
    *   Code pattern scanning.
    *   File hashing.
    *   Lua variable inspection.
    *   API hook detection.
    *   Driver detection.
    *   Timing anomaly detection.
4.  **Flag Management**: Operators for `ScanFlags`, which control when and how scans are executed (e.g., platform restrictions, login-time vs. in-world execution).

This unit does not manage the scheduling or dispatching of scans; that responsibility lies with `WardenScanMgr`. Instead, `WardenScan` provides the atomic units of work that `WardenScanMgr` loads from the database or constructs programmatically.

## Member-by-Member Behavior

### Flag Operations
The `ScanFlags` enum is a bitmask controlling scan behavior. Four operators are defined to manipulate these flags:
*   **`operator|`**, **`operator&`**, **`operator!`**, **`operator&&`**: Standard bitwise and logical operations cast to/from the underlying integer type. These allow combining flags (e.g., `ScanFlags::Windows | ScanFlags::InitialLogin`) or checking conditions (e.g., `if (!(flags & ScanFlags::Mac))`). They are called by `WardenScanMgr` during scan selection and loading.

### Base Scan Class (`Scan`)
*   **`Scan` (ctor)**: Initializes a scan with a builder function, a checker function, flags, expected request/reply sizes, client build range, and a comment. It asserts that a scan cannot be flagged as both Windows and Mac simultaneously. It retrieves the default penalty value from the server configuration via `World/getConfig#4`.
*   **`~Scan` (dtor)**: Default destructor.
*   **`Build`**: Invokes the stored `m_builder` lambda. This serializes the scan's parameters into a `ByteBuffer` to be sent to the client. Called by `Log.Warden/RequestScans`.
*   **`Check`**: Invokes the stored `m_checker` lambda. This deserializes the client's response from a `ByteBuffer` and returns `true` if the scan failed (i.e., a cheat was detected). Called by `Log.Warden/ReadScanResults`.

### String Hash Scans
These scans verify the integrity of the Warden/Maiev module by having the client hash a random string generated by the server.
*   **`StringHashScan::GetBuilder`**: Generates a random lowercase string (1–255 chars), stores it in the `Warden` object's `m_hashString`, and writes its length and content to the scan buffer. Uses `shared_Util/urand` for randomness.
*   **`StringHashScan::GetChecker`**: Computes SHA1 and MD5 hashes of the server-side `m_hashString`. If the client is not using the "Maiev" module, it also mixes in a magic constant (`0xFEEDFACE`) into the SHA1 calculation. It then compares these server-side hashes against the hashes returned by the client. Returns `true` (failure) if they mismatch. Uses `Generator.SHA1` and `Generator.MD5` for hashing.
*   **`WindowsStringHashScan` (ctor)**: Creates a Windows-specific string hash scan. Inherits from `WindowsScan` and `StringHashScan`. Flags it as `Maiev`-only.
*   **`MacStringHashScan` (ctor)**: Creates a Mac-specific string hash scan. If a module is loaded, it flags as `None`; otherwise, it flags as `Maiev`. This reflects that Mac clients might use a different module structure.

### Windows-Specific Scans
All `Windows...Scan` classes inherit from `WindowsScan`, which automatically adds the `ScanFlags::Windows` flag. They all rely on `WardenWin` to access Windows-specific opcodes and XOR keys.

#### Module Scans
*   **`WindowsModuleScan` (ctors)**: Checks if a specific DLL/module is loaded in the client process.
    *   One constructor takes a `wanted` boolean: fails if the module's presence doesn't match `wanted`.
    *   The other takes a custom `CheckT` checker.
    *   **Builder**: Generates a random seed, computes an HMAC-SHA1 of the module name using that seed, and sends the opcode, seed, and hash. Uses `Generator.HMACSHA1`.
    *   **Checker**: Reads the result byte. Fails if the result (`ModuleFound`) doesn't match the expectation.
    *   **Note**: Module names are converted to uppercase before hashing, as the client expects uppercase names.

#### Memory Scans
*   **`WindowsMemoryScan` (ctors)**: Reads raw memory from the client at a specific offset.
    *   Two constructors take an `expected` byte array: they compare the read memory directly against this array.
    *   Two constructors take a custom `CheckT` checker: they pass the read memory to the custom logic.
    *   Constructors can specify a module name (offset relative to module base) or just a raw offset.
    *   **Builder**: Sends the opcode, module name (if any), offset, and expected length.
    *   **Checker**: Reads the status byte. If successful, it compares the returned memory against `m_expected` using `memcmp`. Returns `true` (failure) if they differ.

#### Code Scans
*   **`WindowsCodeScan` (ctor)**: Searches for a specific byte pattern in executable memory segments.
    *   **Builder**: Generates a seed, computes HMAC-SHA1 of the pattern, and sends the opcode, seed, hash, offset, and pattern length. It selects between `FIND_MEM_IMAGE_CODE_BY_HASH` and `FIND_CODE_BY_HASH` opcodes based on `memImageOnly`.
    *   **Checker**: Fails if the pattern's presence (`PatternFound`) doesn't match the `wanted` flag.

#### File Hash Scans
*   **`WindowsFileHashScan` (ctor)**: Verifies the integrity of a file in the client's MPQ archives.
    *   **Builder**: Sends the opcode and filename.
    *   **Checker**: Reads the success status. If the file was found, it reads the SHA1 hash from the client and compares it to `m_expectedHash` (if provided). Fails if the presence doesn't match `wanted` or if the hash mismatches.

#### Lua Scans
*   **`WindowsLuaScan` (ctors)**: Inspects Lua variables in the client's Lua environment.
    *   One constructor checks for existence (`wanted`).
    *   One constructor checks for a specific `expectedValue`.
    *   One constructor uses a custom `CheckT`.
    *   **Builder**: Sends the opcode and variable name.
    *   **Checker**: Reads the success status. If found, it reads the value string. Fails if the existence/value doesn't match expectations.

#### Hook Scans
*   **`WindowsHookScan` (ctor)**: Detects if an API function has been detoured (hooked).
    *   **Builder**: Sends the opcode, a seed, the expected SHA1 hash of the original function prologue, module/proc names, offset, and length.
    *   **Checker**: Fails if the client reports the function as `Detoured`.

#### Driver Scans
*   **`WindowsDriverScan` (ctor)**: Detects specific kernel-mode drivers (often used by cheats like WoWGlider).
    *   **Builder**: Sends the opcode, a seed, HMAC-SHA1 of the target path, and driver name.
    *   **Checker**: Fails if the driver's presence doesn't match the `wanted` flag.

#### Time Scans
*   **`WindowsTimeScan` (ctor)**: Detects timing anomalies that might indicate a debugger or emulator.
    *   **Builder**: Sends the `CHECK_TIMING_VALUES` opcode.
    *   **Checker**: Uses a custom `CheckT` provided by the caller. The comment notes this can yield false positives on XP emulation modes.

## Cross-Unit Boundaries

*   **`WardenScanMgr`**:
    *   **Called By**: `WardenScanMgr/LoadFromDB` creates instances of various `Windows...Scan` classes when loading scans from the database. `WardenScanMgr/GetRandomScans` uses `ScanFlags` operators to filter scans.
    *   **Collaboration**: `WardenScanMgr` is the factory and scheduler. It instantiates these classes and calls their `Build` and `Check` methods indirectly through the `Scan` interface.
*   **`Log.Warden`**:
    *   **Called By**: `Log.Warden/RequestScans` calls `Scan::Build` to serialize scans into packets. `Log.Warden/ReadScanResults` calls `Scan::Check` to validate responses.
    *   **Collaboration**: `Log.Warden` handles the network I/O. It iterates over active scans, builds the request packet, sends it, receives the response, and checks the result.
*   **`Warden` / `WardenWin`**:
    *   **Calls Out**: All Windows scan builders call `WardenWin::GetModule()` to retrieve opcodes and `WardenWin::GetXor()` to encrypt the opcode. `StringHashScan` accesses `Warden::m_hashString` and `Warden::IsUsingMaiev()`.
    *   **Collaboration**: The `Warden` object holds the state of the current Warden session, including the encryption key and module information. The scans use this to format their requests correctly for the specific client instance.
*   **`World`**:
    *   **Calls Out**: `Scan` constructor calls `World/getConfig#4` to get `CONFIG_UINT32_AC_WARDEN_DEFAULT_PENALTY`.
    *   **Collaboration**: Retrieves server-wide configuration settings.
*   **`ByteBuffer`**:
    *   **Calls Out**: Extensively used in `Build` and `Check` lambdas to serialize/deserialize data.
    *   **Collaboration**: Provides the binary buffer abstraction for network packets.
*   **`Crypto/Hash` (SHA1, MD5, HMACSHA1)**:
    *   **Calls Out**: Used in builders/checkers to compute and verify hashes.
    *   **Collaboration**: Provides cryptographic primitives for integrity checks.
*   **`shared_Util`**:
    *   **Calls Out**: `urand` and `rand32` are used for generating random seeds and strings.
    *   **Collaboration**: Provides utility functions for randomness.
*   **`Errors`**:
    *   **Calls Out**: `PrintStacktraceAndThrow` is called in several constructors if preconditions fail (e.g., invalid buffer positions).
    *   **Collaboration**: Handles fatal errors during scan construction.

## Data Model

This unit does not directly interact with database tables. It relies on `WardenScanMgr/LoadFromDB` to instantiate scan objects based on data retrieved from the database. The specific table schemas are not defined in this unit, but the constructors imply the following data fields are likely stored in the `warden_scan` table (or similar):
*   `scan_type`: Determines which class to instantiate.
*   `comment`: Stored in `Scan::comment`.
*   `flags`: Stored in `Scan::flags`.
*   `min_build`, `max_build`: Stored in `Scan::buildMin/buildMax`.
*   Specific parameters (e.g., `module_name`, `offset`, `expected_hash`) are passed to the respective constructors.

## Notable Implementation Details

1.  **XOR Encryption**: All Windows scan opcodes are XORed with a key obtained from `WardenWin::GetXor()`. This obfuscates the scan type from casual packet inspection.
2.  **HMAC-SHA1 for Integrity**: Many scans (Module, Code, Driver) use HMAC-SHA1 with a random seed to verify data integrity. This prevents clients from spoofing hashes by replaying old values.
3.  **Case Sensitivity**: `WindowsModuleScan` and `WindowsMemoryScan` convert module names to uppercase. This is critical because the client's `GetModuleHandle` is case-insensitive, but the HMAC hash is sensitive to case. Consistency ensures the server and client compute the same hash.
4.  **Maiev vs. Module**: `StringHashScan` behaves differently depending on whether the client is using the "Maiev" module. If not, it includes a magic constant in the SHA1 calculation. This allows the server to distinguish between different Warden implementations.
5.  **False Positives**: `WindowsTimeScan` is noted to potentially produce false positives on Windows XP emulation modes. The `CheckT` lambda provided by the caller must account for this.
6.  **Memory Safety**: Several constructors assert that expected data sizes fit within `uint8` limits (e.g., `MANGOS_ASSERT(m_expected.size() <= 0xFF)`). This ensures the protocol remains compact and predictable.
7.  **Deleted Default Constructor**: `Scan::Scan()` is deleted, forcing all scans to be initialized with valid builder/checker pairs. This prevents the creation of empty or invalid scan objects.

## Member Reference

**operator|**
Bitwise OR for `ScanFlags`. Combines flags. Called by `WardenScanMgr`.

**operator&**
Bitwise AND for `ScanFlags`. Intersects flags. Called by `WardenScanMgr`.

**operator!**
Logical NOT for `ScanFlags`. Checks if flags are zero. Called by `WardenScanMgr`.

**operator&&**
Logical AND for `ScanFlags`. Checks if both operands are non-zero.

**Scan**
Constructor for `Scan`. Initializes builder, checker, flags, sizes, build range, and comment. Asserts mutual exclusivity of Windows/Mac flags. Loads default penalty from config.

**GetBuilder**
Method of `StringHashScan`. Returns a lambda that generates a random string, stores it in the Warden object, and serializes it to the buffer.

**Scan#2**
Declaration of `Scan` class.

**~Scan**
Default destructor for `Scan`.

**GetChecker**
Method of `StringHashScan`. Returns a lambda that computes SHA1/MD5 hashes of the stored string (with optional magic constant) and compares them to the client's response.

**Build**
Method of `Scan`. Invokes the builder lambda to serialize the scan request. Called by `Log.Warden/RequestScans`.

**Check**
Method of `Scan`. Invokes the checker lambda to validate the client response. Returns `true` if a cheat is detected. Called by `Log.Warden/ReadScanResults`.

**WindowsStringHashScan**
Constructor for `WindowsStringHashScan`. Creates a Windows-specific string hash scan, flagged as `Maiev`.

**MacStringHashScan**
Constructor for `MacStringHashScan`. Creates a Mac-specific string hash scan. Flags depend on whether a module is loaded.

**WindowsModuleScan#2**
Constructor for `WindowsModuleScan` with a custom checker. Checks for module presence using HMAC-SHA1. Converts module name to uppercase. Called by `WardenScanMgr/LoadFromDB`.

**WindowsModuleScan**
Constructor for `WindowsModuleScan` with a `wanted` boolean. Checks for module presence using HMAC-SHA1. Converts module name to uppercase.

**WindowsMemoryScan#3**
Constructor for `WindowsMemoryScan` with a custom checker and no module name. Reads memory at a raw offset. Called by `WardenScanMgr/LoadFromDB`.

**WindowsMemoryScan**
Constructor for `WindowsMemoryScan` with expected bytes and no module name. Compares memory at a raw offset against expected bytes. Called by `WardenScanMgr/LoadFromDB`.

**WindowsMemoryScan#4**
Constructor for `WindowsMemoryScan` with a custom checker and module name. Reads memory at an offset relative to a module.

**WindowsMemoryScan#2**
Constructor for `WindowsMemoryScan` with expected bytes and module name. Compares memory at an offset relative to a module against expected bytes. Converts module name to uppercase. Called by `WardenScanMgr/LoadFromDB`.

**WindowsCodeScan**
Constructor for `WindowsCodeScan`. Searches for a byte pattern in executable memory using HMAC-SHA1. Called by `WardenScanMgr/LoadFromDB`.

**WindowsFileHashScan**
Constructor for `WindowsFileHashScan`. Verifies the SHA1 hash of a file in the client's MPQs. Called by `WardenScanMgr/LoadFromDB`.

**WindowsLuaScan#3**
Constructor for `WindowsLuaScan` with a custom checker. Inspects a Lua variable. Called by `WardenScanMgr/LoadFromDB`.

**WindowsLuaScan#2**
Constructor for `WindowsLuaScan` with an expected value. Inspects a Lua variable and compares its value. Called by `WardenScanMgr/LoadFromDB`.

**WindowsLuaScan**
Constructor for `WindowsLuaScan` with a `wanted` boolean. Checks for the existence of a Lua variable.

**WindowsHookScan**
Constructor for `WindowsHookScan`. Detects if an API function is detoured by comparing its prologue hash. Called by `WardenScanMgr/LoadFromDB`.

**WindowsDriverScan**
Constructor for `WindowsDriverScan`. Detects specific kernel-mode drivers using HMAC-SHA1. Called by `WardenScanMgr/LoadFromDB`.

**WindowsTimeScan**
Constructor for `WindowsTimeScan`. Checks for timing anomalies using a custom checker.
