# CreatureAI

`CreatureAI` is the base class for all non-player character (NPC) artificial intelligence in the server. It provides the default behavior for creatures that do not require complex scripted logic, handling fundamental combat mechanics such as chasing targets, melee attacking, and casting spells defined in static configuration templates. It also serves as the interface through which the core engine notifies AI implementations of game events (e.g., taking damage, entering combat, dying), allowing derived classes to override specific behaviors while inheriting standard utility functions.

The class manages two primary states via boolean flags: `m_bMeleeAttack` and `m_bCombatMovement`. These determine whether the creature performs automatic melee swings and chases its target, respectively. These states are initialized based on the creature's static flags (`CREATURE_STATIC_FLAG_NO_MELEE` and `CREATURE_STATIC_FLAG_SESSILE`) and can be dynamically toggled during combat, particularly when casting ranged spells.

## Member-by-Member Behavior

### Initialization and Lifecycle
*   **CreatureAI**: The constructor initializes the AI with a pointer to the owning `Creature`. It sets the initial melee and movement states based on the creature's static flags and loads the default spell list associated with the creature's entry.
*   **~CreatureAI**: The destructor is empty, as the AI object is typically managed by the `Creature` object itself.
*   **JustRespawned**: Called when a creature respawns. It resets the spell list to the default template and restores `m_bCombatMovement` and `m_bMeleeAttack` to their default states based on static flags. This ensures that any temporary changes made during the previous life (such as disabling movement for a spell) are cleared.
*   **OnCombatStop**: Similar to `JustRespawned`, this resets the spell list and combat states when the creature leaves combat without dying.
*   **EnterEvadeMode**: Handles the logic for when a creature loses aggro and returns to its home position. If the creature is alive and not charmed, it removes resettable auras, clears its motion master, and moves it home. It also clears the threat list and stops combat. Crucially, it iterates over all controlled units (pets, guardians, totems) using the `EnterEvadeModeHelper` functor to ensure they also evade or are dismissed (totems are unsummoned).
*   **OnRemoveFromWorld** / **CorpseRemoved**: Virtual hooks for cleanup when the creature is removed from the map or its corpse is cleaned up. The base implementation is empty.

### Combat Engagement
*   **AttackedBy**: Called when the creature is attacked. If the creature does not already have a victim, it triggers `AttackStart` with the attacker.
*   **AttackStart**: Initiates combat with a target. It first checks if the creature is passive; if so, it returns immediately. Otherwise, it attempts to attack the victim. If successful, it adds the victim to the threat list, sets both entities as in combat with each other, and starts chasing the victim if combat movement is enabled.
*   **DoMeleeAttackIfReady**: A helper that performs a melee attack if `m_bMeleeAttack` is true and the internal swing timer is ready. It delegates to `Creature::UpdateMeleeAttackingState`.
*   **SetMeleeAttack**: Toggles the `m_bMeleeAttack` flag. If enabling, it adds the `UNIT_STATE_MELEE_ATTACKING` state and sends the start animation. If disabling, it clears the state and sends the stop animation. This is often used to pause melee attacks while casting a spell.
*   **SetCombatMovement**: Toggles the `m_bCombatMovement` flag. If disabling while chasing, it stops the chase and moves idle. If enabling while idle, it resumes chasing the current victim.

### Spell Casting System
`CreatureAI` implements a system for automatically casting spells defined in a `creature_spells` template. This allows NPCs to have periodic abilities (like a fire breath every 10 seconds) without explicit scripting.

*   **SetSpellsList**: Two overloads exist. One takes a template ID, retrieves the data from `ObjectMgr`, and calls the other. The second takes a pointer to the spell list structure, copies the entries into `m_CreatureSpells`, and resets the casting delay timer. If the template ID is invalid, it logs an error.
*   **UpdateSpellsList**: Called periodically (typically from `UpdateAI`). It manages a global delay timer (`m_uiCastingDelay`) to synchronize spell updates. Once the delay expires, it calls `DoSpellsListCasts` with the accumulated time difference.
*   **DoSpellsListCasts**: Iterates through `m_CreatureSpells`. For each spell:
    1.  Decrements the cooldown.
    2.  If the cooldown expires, it checks if the spell can be cast. Spells with `CF_TRIGGERED` or `CF_INTERRUPT_PREVIOUS` flags bypass the check for whether another spell is currently casting.
    3.  It resolves the target using `ScriptMgr::GetTargetByType`.
    4.  It attempts to cast the spell via `Creature::TryToCast`.
    5.  If successful, it sets the next cooldown randomly between `delayRepeatMin` and `delayRepeatMax`. If the spell is a main ranged spell (`CF_MAIN_RANGED_SPELL`), it stops movement and disables melee attacks.
    6.  If the cast fails due to chance (`SPELL_FAILED_TRY_AGAIN`), it resets the cooldown. Other failures generally leave the cooldown at zero so it retries next tick, unless it's a hard failure.
*   **DoCastSpellIfCan**: A convenience wrapper around `Creature::TryToCast` that uses a 100% chance threshold.
*   **DoCast** / **DoCastAOE**: Helper functions to cast a specific spell on a victim or as an Area of Effect. They include checks to prevent casting if the creature is already casting a non-melee spell (unless the new cast is triggered).

### Stealth and Alert Mechanics
*   **OnMoveInStealth**: Called when a unit enters the stealth detection range. It checks if an alert should be triggered via `CanTriggerAlert`.
*   **CanTriggerAlert**: Returns `true` if the creature is an NPC, not in combat, not immobilized, hostile to the intruder, within line of sight, and hasn't alerted recently (10-second cooldown).
*   **TriggerAlertDirect**: Executes the alert behavior: plays an alert sound, faces the intruder, and enters a "distracted" movement state for 5 seconds. It updates the last alert time to enforce the cooldown.

### Utility and Hooks
*   **ClearTargetIcon**: Iterates through all players in the creature's map, identifies unique groups, and clears any raid/target icons placed on this creature by those groups.
*   **GetAIInformation** / **GetData**: Virtual hooks for debug commands or script data retrieval. Base implementations are empty or return 0.
*   **MoveInLineOfSight** / **EnterCombat** / **JustReachedHome** / **HealedBy** / **DamageDeal** / **DamageTaken** / **JustDied** / **SummonedCreatureJustDied** / **GroupMemberJustDied** / **KilledUnit** / **OwnerKilledUnit** / **JustSummoned** / **SummonedCreatureDespawn** / **SpellHit** / **SpellHitTarget** / **MovementInform** / **SummonedMovementInform** / **ReceiveEmote** / **OwnerAttackedBy** / **OwnerAttacked** / **OnScriptEventHappened**: These are virtual event handlers. The base class provides empty implementations (or minimal defaults like `AttackedBy` calling `AttackStart`) to allow derived classes to override specific events without implementing the entire interface.
*   **CanBeLooted** / **FillLoot**: Default to allowing loot but providing no custom loot table. Derived classes can override `FillLoot` to generate dynamic loot.
*   **IsCombatMovementEnabled** / **IsMeleeAttackEnabled**: Accessors for the internal state flags.
*   **SwitchAiAtControl** / **SetUseAiAtControl**: Manages a flag indicating if the AI should be active when the creature is controlled (e.g., by a charm).

They rely on `CreatureAI` for basic combat initiation (`AttackStart`), spell casting (`DoCastSpellIfCan`, `DoSpellsListCasts`), and state management (`SetMeleeAttack`, `SetCombatMovement`). *   **Map.ScriptCommands**: Triggers `OnScriptEventHappened` and `AttackStart` via scripted events.

## Data Model

This unit does not directly interact with database tables. It relies on data loaded into memory by `ObjectMgr` (specifically `GetCreatureSpellsList`), which presumably reads from a `creature_spells` table or similar DBC/scripted data source. No SQL queries are executed within this unit.

## Notable Implementation Details

*   **Spell Casting Synchronization**: The `UpdateSpellsList` method uses a `m_uiCastingDelay` variable to ensure that spell checks happen at regular intervals (defined by `CREATURE_CASTING_DELAY`, 1200ms). It calculates `uiDesync` to adjust for timing drift, ensuring consistent behavior regardless of update tick variance.
*   **Single Spell Cast Per Tick**: In `DoSpellsListCasts`, the flag `bDontCast` prevents multiple non-triggered spells from casting in the same update cycle. Once a spell is cast successfully (and isn't triggered), subsequent spells in the list are skipped for that tick, even if their cooldowns expire. This prevents "spell spamming" and ensures sequential casting.
*   **Ranged Spell Movement Pause**: When a spell with the `CF_MAIN_RANGED_SPELL` flag is cast, `SetCombatMovement(false)` and `SetMeleeAttack(false)` are called. This makes the creature stand still and stop swinging, mimicking client-side behavior for casting heavy spells. If the cast fails (e.g., `SPELL_FAILED_TRY_AGAIN`), these states are restored.
*   **Stealth Alert Cooldown**: `CanTriggerAlert` enforces a 10-second cooldown (`m_uLastAlertTime`) to prevent creatures from constantly alerting to the same stealthed player.
*   **Totem Handling in Evade**: The `EnterEvadeModeHelper` functor explicitly checks for totems (`unit->ToCreature()->IsTotem()`) and unsummons them, whereas other controlled units are just moved home and have their threat lists cleared. This reflects the game mechanic where totems are destroyed when the caster evades or dies.
*   **Passive Creatures**: `AttackStart` immediately returns if the creature has `REACT_PASSIVE`, preventing passive NPCs from engaging in combat even if attacked.
