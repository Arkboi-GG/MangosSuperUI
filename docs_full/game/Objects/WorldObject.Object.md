# WorldObject.Object

## Purpose & Responsibilities

The `WorldObject.Object` unit, implemented in `Object.cpp` and declared in `Object.h`, provides the foundational abstraction for all entities existing within the game world in the WoWVMaNGOS emulator. It defines the base classes `Object` and `WorldObject`, which serve as the root of the entity hierarchy for items, corpses, creatures, players, game objects, and dynamic spell effects.

Its primary responsibilities are:
1.  **Identity and State Management:** Managing the unique identifier (GUID), entry ID, and the core data fields (`m_uint32Values`, `m_floatValues`) that define an object's properties. It implements a mirroring mechanism (`m_uint32Values_mirror`) to track changes for efficient network synchronization.
2.  **Network Synchronization:** Building and sending update packets (`UpdateData`) to clients. This includes handling creation packets, value updates, movement updates, and destruction notifications. It implements complex visibility rules, ensuring clients only receive data for objects they can see or interact with.
3.  **Spatial Awareness:** Providing methods to query and manipulate an object's position (X, Y, Z, Orientation) within the world. It handles coordinate transformations, including offsets relative to moving transports (ships/flies).
4.  **Geometric Calculations:** Offering utilities for distance measurement, line-of-sight (LOS) checks, arc calculations, and finding nearby objects (creatures, game objects, players) within specific ranges.
5.  **Interaction Logic:** Defining basic interaction rules such as faction reactions, attack validity, and helpful target validity, which are refined by derived classes like `Unit`.
6.  **Lifecycle Management:** Handling the addition and removal of objects from the world grid, managing delayed actions (like deferred deletion), and cleaning up references before destruction.

This unit does not touch any database tables directly; all database interactions are performed by derived classes (e.g., `Player.LoadFromDB`, `Creature.SaveToDB`).

## Member-by-Member Behavior

### Initialization and Lifecycle

*   **Object**: The default constructor initializes the object's type ID, type mask, and internal pointers to null. It sets up the initial state flags (`m_inWorld`, `m_deleted`, etc.).
*   **~Object**: The destructor performs safety checks. If the object is still marked as being in the world or has pending updates, it logs an error and asserts, preventing memory corruption. It frees the memory allocated for value arrays.
*   **~WorldObject**: The destructor for `WorldObject` is virtual and empty, relying on derived classes to perform specific cleanup before calling the base destructor.
*   **_InitValues**: Allocates and zeroes out the `m_uint32Values` and `m_uint32Values_mirror` arrays based on `m_valuesCount`.
*   **_Create**: Initializes the object's GUID, entry, and type in its value fields. It is called by derived classes during construction.
*   **_Create#2**: An overload of `_Create` specific to `WorldObject` that takes a `HighGuid` instead of an entry, delegating to `Object::_Create` with entry 0.
*   **WorldObject**: The constructor initializes world-specific members like `m_currMap`, `m_mapId`, `m_instanceId`, and `m_movementInfo`. It sets the initial movement time.
*   **CleanupsBeforeDelete**: Removes the object from the world and, if it is a unit on a transport, removes it as a passenger from that transport. This is called before deletion to ensure clean state.

### Value Management and Updates

*   **SetInt32Value**, **SetUInt32Value**, **SetFloatValue**, **SetByteValue**, **SetUInt16Value**: These setters update the corresponding value in the `m_uint32Values` or `m_floatValues` array. They compare the new value with the old one; if different, they mark the object for client update via `MarkForClientUpdate()`.
*   **SetUInt64Value**: Sets a 64-bit value across two 32-bit slots. It ensures both slots are marked for update to prevent client-side desynchronization issues with packed GUIDs.
*   **SetStatFloatValue**, **SetStatInt32Value**: Convenience setters that clamp negative values to zero before setting.
*   **ApplyModUInt32Value**, **ApplyModInt32Value**, **ApplyModSignedFloatValue**, **ApplyModPositiveFloatValue**: These apply additive modifiers to values. `ApplyModPositiveFloatValue` clamps the result to zero if negative.
*   **SetFlag**, **RemoveFlag**, **SetByteFlag**, **RemoveByteFlag**, **SetShortFlag**, **RemoveShortFlag**: Bitwise operations to set or clear specific flags within value fields. They trigger client updates if the value changes.
*   **ForceValuesUpdateAtIndex**: Forces a specific index to be considered changed by incrementing its mirror value, triggering an update even if the actual value hasn't changed.
*   **MarkForClientUpdate**: Adds the object to the client update list if it is in the world. For non-item objects, it uses a delayed action to batch updates.
*   **ExecuteDelayedActions**: Processes pending delayed actions, such as marking for client update or adding to the remove list.
*   **ClearUpdateMask**: Resets the mirror values to match the current values, clearing the "dirty" state. If `remove` is true, it also removes the object from the client update list.
*   **LoadValues**: Parses a space-separated string of integers and loads them into `m_uint32Values`. Used for debugging or legacy data loading.
*   **_LoadIntoDataField**: Loads a subset of values from a tokenized string starting at a specific offset.
*   **GetUpdateFieldFlagsForTarget**: Determines which update field flags (public, private, owner-only, etc.) are visible to a specific target player, used to construct update masks.

### Network Communication

*   **BuildCreateUpdateBlockForPlayer**: Constructs the packet block sent to a client when an object first becomes visible. It includes movement data, type information, and an update mask of initial values.
*   **BuildValuesUpdateBlockForPlayer**: Constructs the packet block for updating existing object values. It calculates the difference between current and mirrored values to build an efficient update mask.
*   **BuildValuesUpdateBlockForPlayer#2**: An overload that accepts an `UpdateMask` and a `Player` target, delegating to the main build logic.
*   **BuildValuesUpdateBlockForPlayerWithFlags**: Builds an update block for fields matching specific flags (e.g., public fields only), useful for targeted updates.
*   **BuildMovementUpdateBlock**: Constructs the packet block for movement updates.
*   **BuildOutOfRangeUpdateBlock**: Constructs a packet block indicating the object is out of range.
*   **SendCreateUpdateToPlayer**: Sends the creation update packet to a specific player.
*   **SendForcedObjectUpdate**: Forces an immediate update of all changed values to all viewers, bypassing the normal batching.
*   **SendOutOfRangeUpdateToPlayer**: Sends the out-of-range notification to a specific player.
*   **DestroyForPlayer**: Sends the `SMSG_DESTROY_OBJECT` packet to a specific player, removing the object from their client view.
*   **DestroyForNearbyPlayers**: Finds all players who can see the object and sends them the destroy packet. It also cleans up visibility lists and broadcaster listeners.
*   **SendMessageToSet**: Broadcasts a packet to all players who have the object in their visible list.
*   **SendObjectMessageToSet**: Similar to `SendMessageToSet`, but uses a visitor pattern to iterate through cameras and grids efficiently.
*   **SendMovementMessageToSet**: Sends movement packets, with special handling for player broadcasters if enabled.
*   **SendMessageToSetInRange**: Broadcasts a packet to all players within a specified distance.
*   **SendMessageToSetExcept**: Broadcasts a packet to all viewers except a specified player.
*   **SendObjectSpawnAnim**, **SendObjectDeSpawnAnim**: Sends visual animation packets for spawning/despawning.
*   **PlayDistanceSound**, **PlayDirectSound**, **PlayDirectMusic**: Sends audio packets to viewers or a specific target.
*   **DirectSendPublicValueUpdate**: Sends a direct update packet for specific value indices to all viewers.
*   **DirectSendPublicValueUpdate#2**: An overload accepting an `UpdateMask` to specify which fields to update.
*   **DirectSendPublicValueUpdate#3**: An overload accepting an initializer list of indices for concise syntax.

*   **CorrectData**: Validates and corrects movement flags received from the client, removing contradictory flags (e.g., rooted and moving) to prevent client freezes.
*   **Read**, **FillFrom**, **Write**: Serialization methods for `MovementInfo`, reading/writing movement data to/from byte buffers.
