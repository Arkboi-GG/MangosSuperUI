# ObjectMgr

## Purpose & Responsibilities

`ObjectMgr` is the central singleton repository for static world data, configuration, and runtime state management in the WoWVMaNGOS server. It acts as the primary interface for loading, caching, and querying definitions for entities such as creatures, game objects, items, quests, NPCs, and factions. Beyond static data, it manages dynamic systems including:

1.  **Global Identifiers:** Generation and tracking of unique GUIDs for players, items, groups, guilds, mail, and auctions.
2.  **Player Caching:** Maintaining an in-memory cache of offline player data (names, positions, levels) to facilitate lookups without hitting the database.
3.  **World State Variables:** Managing persistent server-side variables used by events (e.g., War Effort, Elemental Invasions) via the `variables` table.
4.  **Localization:** Handling locale-specific strings for creatures, items, quests, gossip, and broadcast texts.
5.  **Spatial Indexing:** Maintaining grid-based indices for static creature and game object spawns to optimize loading and lookup.
6.  **Validation & Correction:** Applying patch-specific corrections to item effects, creature display IDs, and validating database integrity during load.

It is instantiated as a singleton (`sObjectMgr`) and is heavily relied upon by almost every other subsystem, including `Player`, `Creature`, `GameObject`, `ScriptMgr`, `ChatHandler`, and `WorldSession`.

## Member-by-Member Behavior

### Initialization & Data Loading

The `ObjectMgr` loads vast amounts of data from the `world` and `character` databases during server startup. Most `Load*` methods follow a similar pattern: clear existing caches, execute a SQL query, iterate through results, validate data against other loaded sets (e.g., checking if a creature template exists before loading its spells), and populate internal maps.

*   **LoadAllIdentifiers**: Populates `std::set` containers (`m_ItemIdSet`, `m_QuestIdSet`, etc.) with all existing IDs from their respective template tables. This allows for fast O(1) existence checks (`IsExistingItemId`, etc.) throughout the server without needing to load full object definitions. It calls `SpellMgr/LoadExistingSpellIds` to synchronize spell IDs.
*   **LoadSpellDisabledEntrys**, **LoadMapLootDisabled**: Loads lists of disabled spells and maps where loot is disabled from `spell_disabled` and `map_loot_disabled` respectively. Used by `Spell/Main/prepare` and `Player/Main/SendLoot` to enforce restrictions.
*   **LoadCinematicsWaypoints**: Loads cinematic camera paths from `cinematic_waypoints`. Used by `Player/Main/UpdateCinematic` to move the player's camera during cutscenes.
*   **LoadPlayerPhaseFromDb**: Loads world phase masks for all characters from the `characters` table. This supports the phasing system, allowing different players to see different states of the world.
*   **LoadSavedVariable**, **LoadVariable**: Loads persistent server variables from the `variables` table. These are used by complex events (like the War Effort) to maintain state across server restarts. `LoadVariable` also clamps values to min/max bounds.
*   **LoadPlayerCacheData**: Loads essential data for all characters (name, race, class, level, position) from the `characters` table into `m_playerCacheData`. This enables fast lookups for offline players via `GetPlayerDataByGUID` and `GetPlayerGuidByName`.
*   **LoadCreatureTemplates**, **LoadCreatureTemplate**: Loads creature definitions from `creature_template`. It selects the latest patch version compatible with the server's configured patch. It calls `LoadCreatureInfo` to parse fields and `CheckCreatureTemplate` to validate data (e.g., ensuring display IDs exist, probabilities sum correctly).
*   **LoadCreatures**: Loads static creature spawns from the `creature` table, joining with `game_event_creature`, `pool_creature`, and `pool_creature_template`. It validates positions, health/mana percentages, and spawn flags. It adds valid spawns to the grid via `AddCreatureToGrid`.
*   **LoadGameobjects**, **LoadGameObjectTemplates**: Similar to creatures, loads static game object spawns and their definitions from `gameobject` and `gameobject_template`. Validates rotations, states, and display IDs. Adds to grid via `AddGameobjectToGrid`.
*   **LoadItemPrototypes**: Loads item definitions from `item_template`. Performs extensive validation: checks for valid classes, subclasses, qualities, inventory types, required skills/spells/factions, and stack limits. It also calls `CorrectItemEffects` and `CorrectItemDisplayIds` to apply patch-specific fixes for items whose spell effects or models changed between client versions.
*   **LoadQuests**: Loads quest definitions from `quest_template`. Performs deep validation of quest chains, prerequisites, rewards, and objectives. It builds reverse mappings for previous quests and breadcrumb quests. It marks items involved in quests as "discovered" in the item prototype cache.
*   **LoadGroups**: Loads active groups from `groups` and `group_member` tables, reconstructing `Group` objects in memory. It also loads instance bindings from `group_instance` and `instance`.
*   **LoadFactions**, **LoadFactionTemplates**: Loads faction definitions and templates from `faction` and `faction_template`. Handles localized names for 1.12.1 builds.
*   **LoadReputationRewardRate**, **LoadReputationOnKill**, **LoadReputationSpilloverTemplate**: Loads reputation modification rules from their respective tables.
*   **LoadAreaTriggers**, **LoadQuestAreaTriggers**, **LoadTavernAreaTriggers**, **LoadBattlegroundEntranceTriggers**: Loads various types of area triggers (teleports, taverns, BG entrances, quest objectives) from their respective tables.
*   **LoadTaxiNodes**, **LoadTaxiPathTransitions**: Loads flight path nodes and transition rules.
*   **LoadGossipMenus**, **LoadGossipMenuItems**: Loads gossip menu structures and options. Validates that referenced scripts, conditions, and broadcast texts exist.
*   **LoadTrainers**, **LoadVendors**: Loads NPC trainer and vendor items. Validates that spells are learnable and items exist. Supports both direct NPC assignments and template-based assignments.
*   **LoadPlayerInfo**: Loads player creation data (starting positions, items, spells, actions) and level-based stats (health, mana, attributes) from `playercreateinfo*` and `player_levelstats` tables.
*   **LoadPetLevelInfo**, **LoadPetCreateSpells**: Loads pet statistics and initial spells.
*   **LoadCorpses**: Loads existing corpses from the `corpse` table, joining with `characters` and `guild_member` for display data.
*   **LoadMailTemplate**, **LoadItemTexts**, **LoadPageTexts**: Loads mail templates, item page texts, and page texts.
*   **LoadBroadcastTexts**, **LoadBroadcastTextLocales**: Loads broadcast text entries and their localized variants.
*   **LoadMangosStrings**: Loads server-defined string templates from `mangos_string` (or custom tables) for use in scripts and system messages.
*   **LoadConditions**: Loads condition definitions used by gossip, quests, and spells.
*   **LoadPlayerPremadeTemplates**: Loads pre-made gear and spec templates for bots or quick character setup from `player_premade_*` tables.

### Mutators & Dynamic Updates

*   **SetPlayerWorldMask**: Updates the phase mask for a player in the cache. Note: The database update is commented out in the source, meaning phase changes are only persistent in memory until restart or explicit save elsewhere.
*   **SetSavedVariable**, **InitSavedVariable**, **LoadVariable**: Modifies runtime variables. `SetSavedVariable` can optionally persist to the database immediately.
*   **SaveVariables**: Persists all unsaved runtime variables to the database. Called periodically by `World/Update`.
*   **InsertPlayerInCache**, **UpdatePlayerCache**, **UpdatePlayerCachedPosition**, **DeletePlayerFromCache**, **ChangePlayerNameInCache**: Manages the player cache. Called during login, logout, name change, and deletion.
*   **AddGroup**, **RemoveGroup**: Adds/removes groups from the `m_GroupMap`.
*   **AddVendorItem**, **RemoveVendorItem**: Dynamically modifies vendor items for an NPC, persisting changes to the `npc_vendor` table.
*   **AddGameTele**, **DeleteGameTele**: Adds/removes teleport locations, persisting to `game_tele`.
*   **AddGraveYardLink**, **RemoveGraveYardLink**: Modifies graveyard-to-zone mappings, optionally persisting to `game_graveyard_zone`.
*   **AddCreatureToGrid**, **RemoveCreatureFromGrid**, **AddGameobjectToGrid**, **RemoveGameobjectFromGrid**, **AddCorpseCellData**, **DeleteCorpseCellData**: Updates the spatial index for static spawns. Called by `GameEventMgr` and manual spawn commands.
*   **AddCreData**, **AddGOData**, **MoveCreData**: Creates or moves static spawn data in memory and potentially spawns the object if the grid is loaded. Used by GM commands.
*   **DeleteCreatureData**, **DeleteGOData**: Removes static spawn data from memory and the grid index.
*   **CreateItemText**: Creates a new item text entry, assigning a new ID and saving to `item_text`.
*   **ReturnOrDeleteOldMails**: Processes expired mail, returning items to senders or deleting them. Uses asynchronous callbacks (`SingleMailReturner`, `OldMailsReturner`) to avoid blocking the main thread.

### GUID & ID Generation

*   **Generate** (via `IdGenerator`): Generates the next unique ID for a given type (Guild, Mail, Group, Petition). Checks for overflow and shuts down the server if exhausted.
*   **SetMaxUsedGuid**: Initializes the generator's counter from the database maximum.
*   **GeneratePlayerLowGuid**, **GenerateItemLowGuid**, **GenerateCorpseLowGuid**, **GenerateStaticCreatureLowGuid**, **GenerateStaticGameObjectLowGuid**, **GenerateAuctionID**, **GenerateGuildId**, **GenerateGroupId**, **GenerateItemTextID**, **GenerateMailID**, **GeneratePetitionID**, **GeneratePetNumber**: Specific wrappers for generating IDs for different entity types. Some use reserved ranges (static vs. temporary).
*   **FreeItemLowGuid**, **FreeAuctionID**: Releases IDs back into the pool for reuse.
*   **SetHighestGuids**: Initializes all GUID generators by querying the maximum existing IDs in the database. Also cleans up orphaned item references in other tables.
*   **PackGroupIds**: Renormalizes group IDs to be contiguous starting from 1, updating the database.

### Validation & Utility

*   **normalizePlayerName**: Converts a player name to proper case (first letter uppercase, rest lowercase) using UTF-8/Wide-String conversions.
*   **CheckPlayerName**, **CheckPetName**, **IsValidCharterName**: Validates names against length, reserved words, and allowed character sets (Latin, Cyrillic, East Asian) based on realm configuration.
*   **IsReservedName**: Checks if a name is in the reserved list.
*   **IsExistingItemId**, **IsExistingQuestId**, **IsExistingCreatureId**, **IsExistingGameObjectId**, **IsExistingCreatureGuid**, **IsExistingGameObjectGuid**, **IsExistingAreaTriggerId**, **IsExistingCreatureSpellsId**, **IsExistingVendorTemplateId**, **IsExistingGossipMenuId**, **IsExistingConditionId**: Fast existence checks using the sets populated by `LoadAllIdentifiers`.
*   **IsSpellDisabled**, **IsMapLootDisabled**: Checks if a spell or map loot is disabled.
*   **IsVendorItemValid**: Validates if an item can be added to a vendor, checking for duplicates, forbidden items, and capacity.
*   **CheckCreatureTemplate**, **CheckGameObjectTemplate**: Validates template data integrity after loading.
*   **CorrectCreatureDisplayIds**, **CorrectItemEffects**, **CorrectItemDisplayIds**: Applies patch-specific corrections to display IDs and item spell effects.
*   **GetLanguageDescByID**: Returns language information for a given language ID.
*   **GetSkillRangeType**: Determines how a skill bar should be displayed.
*   **IsPointInAreaTriggerZone**: Geometric check to see if a point is within an area trigger's radius or box.
*   **ApplyPremadeGearTemplateToPlayer**, **ApplyPremadeSpecTemplateToPlayer**: Applies pre-configured gear or specs to a player, leveling them up if necessary and equipping items/learning spells.

## Cross-Unit Boundaries

*   **Called by `World/SetInitialWorldSettings`**: The `World` unit calls numerous `Load*` methods in `ObjectMgr` during server startup to initialize all static data.
*   **Called by `ChatHandler.*`**: Various chat command handlers call `ObjectMgr` to look up data (e.g., `HandleLookupPlayerCharacterCommand` calls `GetPlayerDataByName`), modify data (e.g., `HandleNpcAddVendorItemCommand` calls `AddVendorItem`), or generate IDs (e.g., `HandleCharCreateOpcode` calls `GeneratePlayerLowGuid`).
*   **Called by `Player.Main`**: The `Player` class relies heavily on `ObjectMgr` for quest logic (`GetQuestTemplate`), item data (`GetItemPrototype`), reputation (`GetFactionEntry`), leveling (`GetPlayerLevelInfo`), and cache updates (`UpdatePlayerCache`).
*   **Called by `Creature.Main`**, **`GameObject`**: These units call `ObjectMgr` to retrieve their template data (`GetCreatureTemplate`, `GetGameObjectTemplate`) and spawn data (`GetCreatureData`, `GetGOData`).
*   **Called by `ScriptMgr`**: Scripts often look up entities by ID or GUID using `ObjectMgr` methods.
*   **Calls out to `Database`**: All `Load*` methods query the `WorldDatabase` or `CharacterDatabase`.
*   **Calls out to `SpellMgr`**: Validates spell IDs and retrieves spell entries during loading of creatures, items, and quests.
*   **Calls out to `Log.Main`**: Logs errors, warnings, and loading progress.
*   **Calls out to `ProgressBar`**: Displays loading progress bars for large datasets.
*   **Calls out to `shared_Util`**: Uses utility functions for string conversion (`Utf8toWStr`, `wcharToLower`), random numbers (`urand`), and interpolation (`InterpolateValueAtIndex`).
*   **Calls out to `ObjectAccessor`**: `ReturnOrDeleteOldMails` uses `ObjectAccessor/FindPlayerNotInWorld` to check if players are online.
*   **Calls out to `MapManager`**: Validates map coordinates and retrieves continent instance IDs.
*   **Calls out to `TerrainManager`**: `GetClosestGraveYard` uses `TerrainManager/GetZoneAndAreaId` to determine the zone/area of a location.
*   **Calls out to `DBCStores`**: Validates and retrieves DBC data (e.g., `ChrRacesStore`, `ChrClassesStore`, `CreatureDisplayInfoStore`).
*   **Calls out to `SQLStorage`**: Loads SQL-stored DBC-like data (e.g., `creature_addon`, `page_text`).

## Notable Implementation Details

*   **Patch-Based Loading**: Many `Load*` methods for templates (creature, game object, item, quest, faction, etc.) use subqueries to select the latest patch version compatible with the server's configured `WOW_PATCH`. This allows maintaining multiple versions of the same entity in the database.
*   **Data Validation & Correction**: `ObjectMgr` performs extensive validation during loading. Invalid data is logged, and sometimes corrected in memory (e.g., setting invalid display IDs to 0, swapping min/max levels). `CorrectItemEffects` and `CorrectItemDisplayIds` apply hard-coded fixes for items whose definitions changed between client patches.
*   **Player Cache**: The player cache (`m_playerCacheData`) is a critical optimization. It avoids database queries for common lookups (name by GUID, GUID by name, team, class, account ID). It is updated on login/logout/name change. `GetPlayerClassByGUID` falls back to a DB query if the player is not in the cache, which can be slow.
*   **GUID Generation**: GUIDs are generated using `IdGenerator` templates, which track the next available ID. `SetHighestGuids` initializes these counters from the database. Orphaned item references in other tables are cleaned up during this process.
*   **Asynchronous Mail Processing**: `ReturnOrDeleteOldMails` uses asynchronous database queries and callbacks (`SingleMailReturner`, `OldMailsReturner`) to process expired mail without blocking the main server thread. This is crucial for performance when dealing with large mail queues.
