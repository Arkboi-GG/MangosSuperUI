# ObjectGuid

## Purpose & Responsibilities

`ObjectGuid` is the fundamental identity primitive for all persistent and transient entities within the `wowvmangos` server. It encapsulates a 64-bit integer (`uint64`) that uniquely identifies objects such as Players, Creatures, Items, Game Objects, Corpses, and Transports.

Its responsibilities are threefold:
1.  **Identity Representation:** It provides a structured view of the raw 64-bit GUID, allowing the server to extract the "High" part (object type), the "Entry" part (static definition ID, e.g., creature entry), and the "Counter" part (unique instance ID).
2.  **Generation & Reclamation:** Through the templated `ObjectGuidGenerator` class, it manages the lifecycle of GUID counters. It ensures uniqueness by incrementing a global counter for each object type and reclaims deleted GUIDs into a pool (`m_freedGuids`) to prevent integer overflow during long-running server sessions.
3.  **Network Serialization:** It defines how GUIDs are encoded and decoded in network packets (`ByteBuffer`). It supports both standard 8-byte transmission and a variable-length "packed" format to reduce bandwidth, including specific logic to sanitize incoming player GUIDs against packet manipulation attacks.

## Member-by-Member Behavior

### Identity Construction and Modification

*   **Constructors (`ObjectGuid`, `ObjectGuid#2`–`ObjectGuid#7`):** The class provides multiple constructors to create a GUID from a raw `uint64`, from component parts (High, Entry, Counter), or as an empty zero-initialized object. Some constructors are marked `explicit` or private to prevent accidental implicit conversions that could lead to type confusion (e.g., assigning a raw integer where a typed GUID is expected).
*   **Set:** Updates the internal `m_guid` value with a new `uint64`. This is used when loading objects from the database or receiving them over the network.
*   **Clear:** Resets the internal `m_guid` to zero, effectively making the GUID "empty." This is commonly called when an object is destroyed or when a reference field (like a target or owner) needs to be nulled out.

### Inspection and Type Checking

*   **GetRawValue:** Returns the underlying `uint64` value. Used for hashing, direct comparison, or serialization.
*   **GetHigh / GetHigh#2:** Extracts the top 16 bits of the GUID, which determine the object type (e.g., `HIGHGUID_PLAYER`, `HIGHGUID_UNIT`). This is the primary way the server determines what kind of object a GUID refers to.
*   **GetEntry:** Extracts the middle bits of the GUID (if applicable). For creatures and game objects, this corresponds to the static database entry ID. For players and items, this returns 0.
*   **GetCounter:** Extracts the lower bits of the GUID. This is the unique instance identifier. The number of bits used depends on whether the object type has an "Entry" part.
*   **IsEmpty:** Checks if the GUID is zero. An empty GUID typically signifies "no object" or "null reference."
*   **IsCreature, IsPet, IsPlayer, IsUnit, IsItem, IsGameObject, IsDynamicObject, IsCorpse, IsTransport, IsMOTransport:** Boolean methods that check the `GetHigh()` value against specific constants. These allow code to quickly verify the nature of an object without casting. For example, `IsUnit()` returns true for Creatures, Pets, and Players.
*   **GetTypeId:** Maps the `HighGuid` to a `TypeID` enum, which is often used in network protocols to tell the client what kind of object is being described.
*   **HasEntry / HasEntry#2:** Determines if the specific GUID type includes an "Entry" field in its structure. This affects how the Counter is extracted and how the GUID is parsed.

### String Representation and Debugging

*   **GetTypeName:** Returns a human-readable string for a `HighGuid` (e.g., "Player", "Creature").
*   **GetString:** Constructs a detailed string representation of the GUID. For players, it queries `ObjectMgr/GetPlayerNameByGUID` to include the character's name. It also includes the Entry ID (if present) and the Counter. This is heavily used by chat commands and debug logs to identify objects in admin tools.

### Network Serialization Helpers

*   **ReadAsPacked / ReadAsPackedClientBuildAware:** Returns a `PackedGuidReader` object. This reader is used with stream extraction operators (`>>`) to read a variable-length packed GUID from a `ByteBuffer`. The `ClientBuildAware` variant handles differences between client versions regarding how packed GUIDs are encoded.
*   **WriteAsPacked:** Creates a `PackedGuid` object containing the variable-length encoded version of the GUID, ready to be written to a `ByteBuffer`.

### Comparison Operators

*   **operator!, operator==, operator!=, operator<:** Standard comparison operators. `operator!` is overloaded to return `true` if the GUID is empty, allowing idiomatic checks like `if (!guid)`. Equality checks compare the raw `uint64` values.

## Cross-Unit Boundaries

`ObjectGuid` is a foundational utility class, meaning it is called by virtually every other system in the server. Its interactions are primarily data-centric:

*   **ObjectMgr:** `GetString` calls `ObjectMgr/GetPlayerNameByGUID` to resolve player names for debugging strings. `IsGuidHaveEnPart` is called by `ObjectMgr/SetPlayerWorldMask` and `ObjectMgr/GetPlayerWorldMaskByGUID` to determine how to parse the GUID for world mask operations.
*   **ChatHandler:** Numerous chat command handlers (e.g., `HandleUnitInfoCommand`, `HandleCharacterAIInfoCommand`) call `GetString` to display object information to administrators. They also use constructors to build GUIDs from user input.
*   **WorldSession:** Packet handlers (e.g., `HandleCastSpellOpcode`, `HandleLootOpcode`) use `operator>>` and `ReadAsPacked` to deserialize GUIDs from client packets. They use `ClampPlayerGuid` implicitly via the deserialization operators to secure against malformed packets.
*   **Player/Creature/Unit:** These core entity classes use `ObjectGuid` to store references to owners, targets, pets, and charms. Methods like `Player/Main/LoadFromDB` construct GUIDs from database rows. `Unit/Main/DealDamage` uses `IsPlayer` and `IsCreature` to determine damage logic.
*   **BattleGrounds/Groups/Guilds:** These social and combat systems use `ObjectGuid` to track membership. For example, `game_Group_Group/LoadGroupFromDB` constructs player GUIDs to rebuild group structures. `BattleGroundMgr/RemovePlayer` uses GUIDs to identify which player to remove.
*   **Database Interaction:** `LoadFromDB` (in `ObjectGuidGenerator`) interacts with the `CharacterDatabase` to load the maximum used GUID and reclaim freed ones. It does not touch specific tables directly in the `ObjectGuid` unit itself but relies on the `Database` unit for query execution.

## Data Model

The `ObjectGuid` unit itself does not define database tables. However, the `ObjectGuidGenerator::LoadFromDB` method dynamically queries the `CharacterDatabase` to manage GUID counters. It executes queries like:
1.  `SELECT MAX(\`fieldName\`) FROM \`tableName\`` to find the highest used GUID for a specific object type (e.g., `player.guid`, `creature.guid`).
2.  `SELECT \`fieldName\` FROM \`tableName\` WHERE \`fieldName\` BETWEEN ...` to scan for gaps in the GUID sequence, allowing the server to reuse deleted GUIDs and avoid overflow.

The specific tables queried depend on the object type being managed (e.g., `characters`, `corpse`, `item_instance`, `pet`, etc.), but the logic is generic and driven by the `fieldName` and `tableName` parameters passed to `LoadFromDB`.

## Notable Implementation Details

*   **GUID Structure Variance:** Not all GUIDs have the same bit layout. Types like Players and Items have no "Entry" part, so their Counter uses more bits (32 bits). Types like Creatures and Game Objects have an "Entry" part (24 bits), leaving fewer bits for the Counter (24 bits). The `HasEntry` helper and `GetCounter` logic handle this distinction.
*   **Player GUID Clamping:** The `ClampPlayerGuid` function is a critical security measure. It ensures that if a client sends a player GUID with extra high bits set (e.g., adding multiples of `0xFFFFFFFF+1`), the server strips them back to the valid low GUID range. This prevents potential exploits where a manipulated GUID might bypass certain checks due to hash collisions or unexpected behavior in other parts of the code.
*   **GUID Reclamation:** To prevent the 32-bit counter from overflowing (which would crash the server), `ObjectGuidGenerator` maintains a queue of `m_freedGuids`. When an object is deleted, its counter can be pushed back into this queue. When a new object needs a GUID, the generator checks this queue first. If the queue is empty, it increments the `m_nextGuid`. The `LoadFromDB` method pre-populates this queue at startup by scanning for gaps in the database.
*   **Overflow Protection:** Both `Generate` and `GenerateRange` check if `m_nextGuid` is approaching the maximum limit (`GetMaxCounter`). If it is, they log an error and call `World/StopNow` to shut down the server gracefully, preventing undefined behavior from wrapped-around GUIDs.
*   **Packed GUIDs:** The `PackedGuid` and `PackedGuidReader` classes support a variable-length encoding scheme. This reduces network traffic by omitting leading zero bytes in the GUID. The `ReadAsPackedClientBuildAware` method indicates that the packing algorithm may vary depending on the connected client's version, requiring careful handling in packet parsing.
*   **Thread Safety:** The `ObjectSafeGuidGenerator` template specialization adds mutex locking around `Generate`, `FreeGuid`, and `GenerateRange`. This ensures that GUID generation remains thread-safe in environments where multiple threads might request GUIDs concurrently (though the base `ObjectGuidGenerator` is not thread-safe).

## Member Reference

**GetTypeName**: Returns a static string literal describing the object type associated with a `HighGuid` enum value (e.g., "Player", "Creature").

**GetString**: Constructs a human-readable string representing the GUID. For players, it retrieves the character name via `ObjectMgr/GetPlayerNameByGUID`. It includes the type name, entry ID (if applicable), and counter.

**Set**: Assigns a new `uint64` value to the internal `m_guid` member.

**Generate**: Allocates a new unique counter for a specific object type. It first checks the `m_freedGuids` queue for reusable IDs. If empty, it increments `m_nextGuid`. It shuts down the server if the counter approaches overflow.

**IsGuidHaveEnPart**: A free function that determines if a given `HighGuid` type includes an "Entry" field in its bit structure. Used to correctly parse the Counter portion of the GUID.

**GenerateRange**: Allocates a block of 100 consecutive GUID counters. It checks for overflow before allocating. Used for bulk operations or pre-allocation strategies.

**LoadFromDB**: Queries the `CharacterDatabase` to initialize the GUID generator. It finds the maximum used GUID for a table/column and scans for gaps to populate the `m_freedGuids` queue, enabling GUID reuse.

**ObjectGuid**: Default constructor initializes the GUID to zero (empty).

**ObjectGuid#5**: Constructor that takes a `uint64` value, initializing the GUID directly. Allows implicit conversion from integers, which is noted as potentially risky.

**ObjectGuid#3**: Constructor that builds a GUID from `HighGuid`, `entry`, and `counter` components. Handles the bit-shifting logic to assemble the final 64-bit value.

**ObjectGuid#2**: Constructor that builds a GUID from `HighGuid` and `counter` only, assuming no entry part.

**ObjectGuid#4**: Constructor that builds a GUID from a `lowGuid` (uint32), likely for legacy or specific internal uses.
