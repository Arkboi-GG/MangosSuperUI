# ModelSpawn

**Purpose & Responsibilities**

`ModelSpawn` is a lightweight data structure within the `VMAP` namespace that represents the raw spawn data for a world model in the game world. It acts as a container for the geometric and identification metadata required to place a model (such as a building, bridge, or prop) within a specific map tile. Specifically, it stores the model's unique identifier, its position (`iPos`), rotation (`iRot`), scale (`iScale`), and its axis-aligned bounding box (`iBound`).

This class serves as the base for `ModelInstance`, which adds runtime logic for collision detection and raycasting. `ModelSpawn` itself contains no dynamic behavior beyond equality comparison and bound retrieval; its primary role is to define the static footprint of a model instance as loaded from disk or memory. It is part of the Virtual Map (VMAP) system, which handles height queries, line-of-sight checks, and liquid level calculations by managing these model instances alongside terrain data.

The **operator==** method provides a value-based equality check between two `ModelSpawn` objects. It compares only the `ID` field of the current object with the `ID` field of the other object. This implies that identity in this context is strictly tied to the model's unique identifier, ignoring position, rotation, or scale differences. This is likely used for deduplication or lookup purposes where the specific instance ID is the key discriminator.

### Bounds Retrieval
The **getBounds** method returns a constant reference to the `iBound` member, which is a `G3D::AABox` (Axis-Aligned Bounding Box). This allows external systems to quickly determine the spatial extent of the model without computing it dynamically. The method is marked `const`, ensuring it does not modify the object's state.

## Notable Implementation Details

1.  **Identity via ID Only**: The `operator==` implementation relies solely on `ID`. This is a significant design choice. If two models have the same ID but different positions (which might happen in certain edge cases or bugs), they would be considered equal. Maintainers should be aware that this equality check is not sufficient for determining if two spawns occupy the same space; it only checks if they refer to the same logical model definition.
2.  **Inheritance Structure**: `ModelSpawn` is designed to be inherited by `ModelInstance`. `ModelInstance` adds the `iModel` pointer (to the actual geometry data) and inverse transformation matrices (`iInvRot`, `iInvScale`) needed for efficient raycasting. `ModelSpawn` holds the "spawn" data (where it goes), while `ModelInstance` holds the "instance" data (what it is and how to collide with it).
3.  **Bounding Box Storage**: The `iBound` member is stored directly in the struct. This avoids the need to compute the bounding box on every query, trading memory for speed. The bounds are likely computed during the loading/extraction phase and stored here.
4.  **Commented-Out Code**: There is commented-out code for `hashCode()` and a question mark next to `getBounds()`. This suggests historical uncertainty about whether hashing was needed or if the bounds getter was temporary. The presence of `getBounds` being called by `TileAssembler` confirms its necessity, but the lack of a hash function implies that `std::map` or linear searches keyed by ID might be used elsewhere, or that `ID` is used directly as a key.

## Member Reference

**operator==**
Compares the `ID` of the current `ModelSpawn` with the `ID` of another `ModelSpawn`. Returns `true` if the IDs match, regardless of position, rotation, or scale. Used for identity checks.

**getBounds**
Returns a constant reference to the `iBound` member (`G3D::AABox`). Provides quick access to the model's axis-aligned bounding box for spatial queries. Called by `BoundsTrait.TileAssembler/getBounds` to aggregate tile bounds.
