# VMapManager2

**Purpose & Responsibilities**

`VMapManager2` is the central runtime manager for Virtual Maps (VMaps) in the CMaNGOS server. It acts as the primary interface for spatial queries regarding terrain height, line-of-sight (LoS) occlusion, liquid levels, and area information. The class manages the lifecycle of `StaticMapTree` instances, which represent the binary space partitioning (BSP) trees for specific game maps. It handles the lazy loading and unloading of map tiles, coordinate system conversions between the game engine’s representation and the internal VMap format, and thread-safe access to shared world model assets (`.vmo` files).

It implements the `IVMapManager` interface, allowing the rest of the server to query spatial data without needing to know the underlying details of how map trees are constructed or stored.

## Member-by-Member Behavior

### Lifecycle and Initialization

*   **`VMapManager2` (ctor)**: Initializes an empty manager. No resources are allocated here; map trees are loaded on demand.
*   **`~VMapManager2` (dtor)**: Cleans up all loaded map trees. It iterates through `iInstanceMapTrees`, deleting each `StaticMapTree` pointer, and clears the `iLoadedModelFiles` cache. Note that `iLoadedModelFiles` stores `ManagedModel` objects (which inherit from `std::weak_ptr`), so clearing the map removes the weak references, allowing the `std::shared_ptr` managed models to be destroyed if no other references exist.

### Coordinate Conversion

*   **`convertPositionToInternalRep`**: Converts game-world coordinates `(x, y, z)` to the internal VMap coordinate system. The transformation is:
    *   `internal_x = (0.5 * 64 * 533.33333333) - x`
    *   `internal_y = (0.5 * 64 * 533.33333333) - y`
    *   `internal_z = z`
    This effectively flips the X and Y axes relative to a center point (`mid ≈ 17066.66`) while keeping Z unchanged. This conversion is critical because the VMap data structures expect coordinates in this specific flipped orientation. All spatial query methods call this before delegating to the `MapTree`.

### Map Loading and Unloading

*   **`loadMap`**: The public entry point for loading a map tile. It first checks `IVMapManager::isMapLoadingEnabled()` (from the parent interface). If enabled, it delegates to `_loadMap`. Returns `VMAP_LOAD_RESULT_OK` on success, `VMAP_LOAD_RESULT_ERROR` on failure, or `VMAP_LOAD_RESULT_IGNORED` if loading is disabled.
*   **`_loadMap`**: Internal helper for loading. It checks `iInstanceMapTrees` for an existing tree for the given `pMapId`.
    *   If no tree exists, it creates a new `StaticMapTree`, initializes it with the map filename (generated by `getMapFileName`), and inserts it into `iInstanceMapTrees`.
    *   It then calls `MapTree::LoadMapTile` on the tree instance to load the specific tile `(tileX, tileY)`.
    *   If initialization fails, the new tree is deleted, and `false` is returned.
*   **`unloadMap` (overload 1)**: Unloads an entire map by ID. It finds the tree in `iInstanceMapTrees`, calls `MapTree::UnloadMap`, and then checks `StaticMapTree::numLoadedTiles()`. If zero tiles remain loaded, the tree itself is deleted and removed from the map.
*   **`unloadMap` (overload 2)**: Unloads a specific tile `(x, y)` of a map. Similar to the full unload, it calls `MapTree::UnloadMapTile` and checks `StaticMapTree::numLoadedTiles()`. If the count drops to zero, the entire tree structure is cleaned up.
*   **`existsMap`**: Checks if a map tile exists on disk. It delegates to `MapTree::CanLoadMap`, passing the base path, map ID, and tile coordinates.
*   **`getMapFileName`**: Generates the standard filename for a map tree file: a 3-digit zero-padded map ID followed by `.vmtree` (defined by `MAP_FILENAME_EXTENSION2`).
*   **`getDirFileName`**: A trivial wrapper that returns the result of `getMapFileName`. It ignores the `x` and `y` parameters.

### Spatial Queries

All spatial queries follow a similar pattern:
1.  Check if the specific calculation type is enabled via `IVMapManager` (e.g., `isLineOfSightCalcEnabled`, `isHeightCalcEnabled`).
2.  Look up the `StaticMapTree` for the given `pMapId` in `iInstanceMapTrees`.
3.  Convert input coordinates using `convertPositionToInternalRep`.
4.  Delegate the query to the corresponding method on the `StaticMapTree` instance.
5.  Convert results back to game coordinates if necessary.

*   **`isInLineOfSight`**: Determines if two points `(x1,y1,z1)` and `(x2,y2,z2)` have a clear line of sight.
    *   Returns `true` immediately if LoS calculation is disabled.
    *   If points are identical, returns `true`.
    *   Delegates to `MapTree::isInLineOfSight`.
*   **`FindCollisionModel`**: Finds the specific `ModelInstance` that blocks the line of sight between two points.
    *   Returns `nullptr` if LoS calculation is disabled.
    *   Delegates to `MapTree::FindCollisionModel`.
*   **`getObjectHitPos`**: Calculates the exact hit position on a model blocking the line of sight.
    *   Initializes output coordinates `(rx, ry, rz)` to the destination `(x2, y2, z2)`.
    *   If LoS is enabled and a hit occurs, it retrieves the internal hit position, converts it back to game coordinates using `convertPositionToInternalRep` (note: the method name suggests "to internal", but here it is used symmetrically to reverse the transform, as the math is its own inverse for X/Y flipping around the midpoint), and updates the output references.
*   **`getHeight`**: Gets the height of the terrain/model at `(x, y)`.
    *   Returns `VMAP_INVALID_HEIGHT_VALUE` if height calculation is disabled or if the tree returns infinity (`G3D::inf()`).
    *   Delegates to `MapTree::getHeight`.
*   **`getAreaInfo`**: Retrieves area flags, ADT ID, root ID, and group ID for a location.
    *   Updates the `z` output parameter with the Z value from the internal position (which is unchanged by the X/Y flip).
    *   Delegates to `MapTree::getAreaInfo`.
*   **`isUnderModel`**: Checks if a point is inside a model.
    *   Delegates to `MapTree::isUnderModel`.
*   **`GetLiquidLevel`**: Retrieves liquid level information at a point.
    *   Delegates to `MapTree::GetLocationInfo` to get a `LocationInfo` struct.
    *   Uses `BoundsTrait.WorldModel::GetLiquidType` to get the raw liquid type.
    *   Calls `GetLiquidMask` (a static helper function) to convert the raw type to a mask.
    *   Checks if the requested `ReqLiquidTypeMask` matches the found liquid type.
    *   If matched, calls `ModelInstance::GetLiquidLevel` to get the precise level.

### Model Asset Management

*   **`acquireModelInstance`**: Thread-safe retrieval of a `WorldModel` asset.
    *   Uses a double-checked locking pattern with `std::shared_timed_mutex`.
    *   First, acquires a shared lock (`slock`) to check `iLoadedModelFiles`.
    *   If the model is not found, unlocks the shared lock, acquires a unique lock (`ulock`), and re-checks (to prevent race conditions).
    *   If still not found, it creates a new `WorldModel`, loads it from `<basepath><filename>.vmo` using `WorldModel::readFile`.
    *   If loading fails, it logs an error via `Log.Main::Out` and deletes the model.
    *   On success, it creates a `std::shared_ptr` with a custom deleter. The deleter checks `IVMapManager::getUseManagedPtrs()`. If managed pointers are disabled, it erases the entry from `iLoadedModelFiles`. Otherwise, it relies on the `ManagedModel` wrapper to handle persistence.
    *   Inserts the new model into `iLoadedModelFiles` wrapped in a `ManagedModel`.
    *   Returns the `shared_ptr`.
*   **`ManagedModel` (ctor)**: A helper class inheriting from `std::weak_ptr<WorldModel>`.
    *   If `managed` is true, it keeps a persistent `shared_ptr` (`m_persistent`) alive, preventing the model from being unloaded even if the `VMapManager2`'s map entries are cleared. This is useful for frequently accessed global models.

### Debug/Utility

*   **`processCommand`**: A stub implementation that always returns `false`. Intended for future debug commands or extensions.

## Cross-Unit Boundaries

*   **`IVMapManager`**: `VMapManager2` inherits from this interface. It calls `isMapLoadingEnabled`, `isLineOfSightCalcEnabled`, `isHeightCalcEnabled`, `getUseManagedPtrs`, and `Log.Main::Out` (via the `sLog` singleton which likely implements or wraps `IVMapManager` logging capabilities). These calls allow the manager to respect global configuration settings for performance tuning (e.g., disabling LoS calculations entirely).
*   **`MapTree` / `StaticMapTree`**: The core dependency. `VMapManager2` creates `StaticMapTree` instances and delegates all heavy spatial computation (LoS, height, area info, liquid levels) to them. It also uses `MapTree::CanLoadMap` to check file existence.
*   **`WorldModel`**: Used in `acquireModelInstance` to load `.vmo` files. `VMapManager2` manages the lifetime of these objects via `shared_ptr`.
*   **`ModelInstance`**: Returned by `FindCollisionModel` and used internally in `GetLiquidLevel` to query specific model properties like liquid levels.
*   **`VMapFactory`**: Calls `VMapManager2` constructor via `createOrGetVMapManager`. This is the factory pattern entry point for creating manager instances.

## Data Model

This unit does not interact directly with database tables. It operates entirely on in-memory data structures (`InstanceTreeMap`, `ModelFileMap`) and files on disk (`.vmtree`, `.vmo`). The `Tables` column in the MAP is empty for all members.

## Notable Implementation Details

1.  **Coordinate System Flip**: The `convertPositionToInternalRep` method performs a non-trivial coordinate transformation. It flips X and Y around a large constant (`mid`). Maintainers must remember that any coordinates passed to `MapTree` methods are in this internal format, and any coordinates returned (like in `getObjectHitPos`) must be converted back. The conversion is symmetric for X and Y, so calling it twice restores the original values.
2.  **Thread Safety for Models**: `acquireModelInstance` uses `std::shared_timed_mutex` to allow concurrent reads of the model cache while serializing writes. The double-checked locking ensures that only one thread loads a specific `.vmo` file, even if multiple threads request it simultaneously.
3.  **Lazy Tree Cleanup**: The `unloadMap` methods do not immediately delete the `StaticMapTree` if tiles are unloaded. They only delete the tree if `numLoadedTiles()` returns 0. This allows for efficient partial unloading of large maps without destroying the entire BSP structure.
4.  **Managed vs. Unmanaged Models**: The `ManagedModel` class and the `getUseManagedPtrs()` check provide a mechanism to keep certain models permanently in memory. If `getUseManagedPtrs()` returns true, the `ManagedModel` holds a strong reference, preventing deletion. If false, the model is only kept alive as long as it is referenced by active map trees or other `shared_ptrs`.
5.  **Liquid Type Mapping**: The `GetLiquidMask` function contains hardcoded mappings from raw liquid type IDs to `MAP_LIQUID_TYPE_*` constants. Notably, type `21` maps to `SLIME` and `41`/`61` map to `WATER`. This suggests specific WotLK-era DBC data handling.
6.  **Invalid Height Handling**: In `getHeight`, if the tree returns `G3D::inf()`, it is treated as "no height" and `VMAP_INVALID_HEIGHT_VALUE` is returned. This prevents infinity values from propagating into game logic.
