# GridMapDefines

**GridMapDefines** is a header-only unit providing the static type definitions (`struct`s, `enum`s, and `#define` constants) required to parse World of Warcraft map data files (`.map`). It contains no executable logic, database interactions, or runtime behavior. Its sole responsibility is to define the binary schema for grid-based terrain information, including heights, liquids, and area types, ensuring that memory layouts match the expected binary layout of map files generated by the WoW client or extraction tools.

## Purpose & Responsibilities

The unit defines the **binary schema** for map data through three primary mechanisms:

1.  **File Header Validation**: The `GridMapFileHeader` structure identifies valid map files via magic numbers (`mapMagic`, `versionMagic`) and locates internal data sections (area maps, height maps, liquid maps, holes).
2.  **Terrain Data Structures**: Specific headers define metadata for grid components:
    *   `GridMapAreaHeader`: Area type identification.
    *   `GridMapHeightHeader`: Height map metadata and scaling factors.
    *   `GridMapLiquidHeader`: Liquid type, level, and presence flags.
3.  **Constant Definitions**: Bitmasks and magic values (e.g., `MAP_HEIGHT_NO_HEIGHT`, `LIQUID_MAP_IN_WATER`) used throughout map parsing logic.
4.  **Navigation Mesh Areas**: The `NavMeshAreas` enumeration categorizes terrain for pathfinding, distinguishing walkable ground from steep slopes or water.

## Member-by-Member Behavior

Since this unit contains no functions, "behavior" refers to the role and interpretation of each defined type and constant.

### File Structure Definitions

*   **`GridMapFileHeader`**: Represents the top-level header of a map file. It contains offsets and sizes for four distinct data sections: `areaMapOffset`/`areaMapSize`, `heightMapOffset`/`heightMapSize`, `liquidMapOffset`/`liquidMapSize`, and `holesOffset`/`holesSize`. The `mapMagic` and `versionMagic` fields verify file integrity and version compatibility before parsing.

### Component Headers

*   **`GridMapAreaHeader`**: Defines the header for an area block. `fourcc` is a 4-character code identifying the data type, `flags` is a bitmask for area-specific properties, and `gridArea` is the specific area ID.
*   **`GridMapHeightHeader`**: Defines metadata for height map data. `fourcc` identifies the block, `flags` indicates storage format (e.g., `int16`, `int8`, or missing), `gridHeight` is the base height, and `gridMaxHeight` is the maximum height used for normalization.
*   **`GridMapLiquidHeader`**: Defines metadata for liquid data blocks. It includes `fourcc`, general `flags`, specific `liquidFlags`, `liquidType`, spatial dimensions (`offsetX`, `offsetY`, `width`, `height`), and `liquidLevel` (absolute surface height).

### Liquid Status and Types

*   **`GridMapLiquidStatus`**: An enumeration representing the result of a liquid query at a specific point: `LIQUID_MAP_NO_WATER`, `LIQUID_MAP_ABOVE_WATER`, `LIQUID_MAP_WATER_WALK`, `LIQUID_MAP_IN_WATER`, or `LIQUID_MAP_UNDER_WATER`.
*   **`MAP_LIQUID_TYPE_*` Constants**: Bitmasks defining liquid types, derived from DBC data and shifted for flag usage. `MAP_ALL_LIQUIDS` combines standard types (water, magma, ocean, slime). Additional types include `MAP_LIQUID_TYPE_DEEP_WATER` and `MAP_LIQUID_TYPE_WMO_WATER`.
*   **`GridMapLiquidData`**: A runtime structure holding aggregated liquid information after parsing. It contains `type_flags` (bitmask), `entry` (DBC entry ID), `level` (surface height), and `depth_level`. Members are default-initialized to zero.

### Navigation and Area Flags

*   **`NavMeshAreas`**: An enumeration for pathfinding and movement logic. Categories include `AREA_NONE`, `AREA_GROUND`, `AREA_GROUND_MODEL`, `AREA_STEEP_SLOPE`, `AREA_STEEP_SLOPE_MODEL`, `AREA_WATER_TRANSITION`, `AREA_WATER`, `AREA_MAGMA`, and `AREA_SLIME`.
*   **Flag Constants**: `MAP_AREA_NO_AREA` (0x0001) indicates no area data. `MAP_HEIGHT_NO_HEIGHT`, `MAP_HEIGHT_AS_INT16`, and `MAP_HEIGHT_AS_INT8` indicate height storage formats. `MAP_LIQUID_NO_TYPE` and `MAP_LIQUID_NO_HEIGHT` indicate missing liquid data.

## Cross-Unit Boundaries

This unit is purely declarative. It does not call into other units. It is **included by** units responsible for:
*   **Map Loading/Parsing**: Interpreting binary data from disk into the defined structs.
*   **Terrain Query Systems**: Returning standardized height/liquid results to NPCs or players.
*   **Pathfinding Engines**: Using `NavMeshAreas` to determine traversable nodes.

## Data Model

This unit does not interact with any database tables. It deals exclusively with binary file formats loaded from disk.

## Notable Implementation Details

1.  **Bitwise Flag Usage**: Constants like `MAP_LIQUID_TYPE_*` are powers of two, allowing combination via bitwise OR. Consumers must use bitwise AND to check flags.
2.  **Endianness Assumptions**: Structs assume little-endian byte order (typical for x86/x64). Big-endian systems require explicit byte-swapping elsewhere, as this header does not handle it.
3.  **Fixed-Size Structs**: Structs match the exact binary layout of map files. Reordering or adding fields breaks parsing.
4.  **Default Initialization**: `GridMapLiquidData` uses in-class member initializers to prevent undefined behavior from uninitialized memory.
5.  **Magic Numbers**: `mapMagic` and `versionMagic` allow parsers to reject invalid files.

## Member Reference

**GridMapFileHeader**
Struct defining the binary header of a map file, containing magic numbers for validation and offsets/sizes for area, height, liquid, and hole data sections.

**MAP_AREA_NO_AREA**
Constant (0x0001) indicating that no area data is present in the map.

**GridMapAreaHeader**
Struct defining the header for an area block within a map, including a four-character code, flags, and the grid area ID.

**MAP_HEIGHT_NO_HEIGHT**
Flag (0x0001) indicating that height data is not present.

**MAP_HEIGHT_AS_INT16**
Flag (0x0002) indicating that height data is stored as 16-bit integers.

**MAP_HEIGHT_AS_INT8**
Flag (0x0004) indicating that height data is stored as 8-bit integers.

**GridMapHeightHeader**
Struct defining metadata for height map data, including a four-character code, flags for storage format, base height, and maximum height.

**MAP_LIQUID_NO_TYPE**
Flag (0x01) indicating that liquid type data is not present.

**MAP_LIQUID_NO_HEIGHT**
Flag (0x02) indicating that liquid height data is not present.

**GridMapLiquidHeader**
Struct defining metadata for liquid data blocks, including identifiers, flags, liquid type, spatial dimensions, and the liquid surface level.

**GridMapLiquidStatus**
Enumeration representing the status of a point relative to liquid: no water, above water, water walk, in water, or under water.

**MAP_LIQUID_TYPE_NO_WATER**
Constant (0x00) representing no liquid type.

**MAP_LIQUID_TYPE_MAGMA**
Constant (0x01) representing magma.

**MAP_LIQUID_TYPE_OCEAN**
Constant (0x02) representing ocean water.

**MAP_LIQUID_TYPE_SLIME**
Constant (0x04) representing slime.

**MAP_LIQUID_TYPE_WATER**
Constant (0x08) representing standard water.

**MAP_ALL_LIQUIDS**
Bitmask combining all standard liquid types (water, magma, ocean, slime).

**MAP_LIQUID_TYPE_DEEP_WATER**
Constant (0x10) representing deep water.

**MAP_LIQUID_TYPE_WMO_WATER**
Constant (0x20) representing water defined by World Model Objects.

**GridMapLiquidData**
Runtime struct holding aggregated liquid information: type flags, DBC entry ID, surface level, and depth level. Members are default-initialized to zero.

**NavMeshAreas**
Enumeration categorizing terrain for pathfinding: none, ground, ground model, steep slope, steep slope model, water transition, water, magma, and slime.
