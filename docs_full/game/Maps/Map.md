# Map

The `Map` class is the central runtime container for a single logical instance of a game world area—whether a continent, a dungeon instance, or a battleground. It acts as the authoritative manager for all entities (players, creatures, game objects, corpses) within that spatial context, handling their lifecycle, visibility, movement updates, and interaction with the server’s grid-based loading system.

## Class Structure

The `Map` class is implemented across two primary partials, each addressing distinct layers of the server’s architecture:

*   **`Map.Main`**: Carries the core engine responsibilities. This partial manages the spatial grid system (loading/unloading grids, cell management), entity registration (adding/removing objects), instance state persistence (dungeon resets, bindings), collision detection (VMaps/MMaps), and the high-level update loops that drive player and creature updates. It also defines the subclass hierarchies for `DungeonMap` and `BattleGroundMap`.
*   **`Map.ScriptCommands`**: Implements the database-driven scripting engine’s action layer. This partial contains the `ScriptCommand_*` methods that execute atomic actions defined in SQL scripts (e.g., talk, move, cast spell, summon creature). It translates script instructions into concrete C++ calls on entities, handling validation, logging, and control flow for scripted events.

## Collaboration Patterns

The `Map` class serves as a hub between the low-level spatial engine and high-level gameplay systems:

*   **Grid & Loading**: `Map.Main` collaborates with `GridMap` and `ObjectGridLoader` to manage the physical presence of data. When a player enters a new area, `Map` ensures the corresponding grid is loaded from disk/memory before the player is added. Conversely, inactive grids are unloaded to free memory.
*   **Entity Interaction**: Entities (`Player`, `Creature`, `GameObject`) register themselves with the `Map` upon creation (`Add`) and unregister upon destruction (`Remove`). The `Map` maintains lookup tables (by GUID) allowing fast retrieval of entities for scripts, spells, and combat logic.
*   **Scripting Bridge**: `Map.Main` exposes query methods (`GetCreature`, `GetGameObject`, `GetInstanceData`) that `Map.ScriptCommands` uses to resolve targets for scripted actions. For example, `ScriptCommand_SummonCreature` calls `Map.Main`’s internal spawning logic to place a new entity into the grid.
*   **Instance State**: For dungeons and raids, `Map.Main` interacts with `InstanceData` and `MapPersistentStateMgr` to save and restore encounter progress. The `instance` database table stores this state, keyed by the map’s instance ID.
*   **Collision & Pathfinding**: `Map.Main` delegates line-of-sight and height queries to `VMapManager` and `MMapManager`, providing a unified interface for spells and movement generators to check terrain validity.

## Data Model

The `Map` class persists instance-specific state in two database tables:

*   **`instance`**: Stores state for individual dungeon/raid instances.
    *   `id` (int(11) unsigned, PK): Unique instance identifier.
    *   `map` (int(11) unsigned): The map ID this instance belongs to.
    *   `reset_time` (bigint(40)): Timestamp for automatic instance reset.
    *   `data` (longtext, nullable): Serialized binary data representing boss states, flags, and other encounter progress.
*   **`world`**: Stores persistent state for non-instanced maps (continents) used by global scripts.
    *   `map` (int(11) unsigned, PK): The map ID.
    *   `data` (longtext, nullable): Serialized script data for world-wide events.
