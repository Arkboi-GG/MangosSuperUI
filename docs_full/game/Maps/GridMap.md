# GridMap: Terrain Data Management

**Purpose & Responsibilities**

The `GridMap` translation unit (`GridMap.cpp`, `GridMap.h`) provides the foundational layer for terrain querying in the wowvmangos server. It is responsible for loading, caching, and interpreting raw terrain data from binary `.map` files (generated by the `ad.exe` tool) and coordinating with Virtual Map (VMap) and Movement Map (MMAP) systems to provide accurate height, liquid, and area information for game entities.

The unit defines three primary classes:
1.  **`GridMap`**: A low-level wrapper for a single terrain grid (a 533.33x533.33 yard square of the world). It parses binary headers and stores height maps, area flags, and liquid data in memory. It exposes methods to interpolate heights and determine liquid states at specific coordinates within that grid.
2.  **`TerrainInfo`**: A mid-level manager for a single Map ID (e.g., Elwynn Forest). It maintains a 32x32 matrix of `GridMap` pointers, handling lazy loading, reference counting, and garbage collection of grids. It acts as the primary interface for game logic to query terrain properties (height, water, outdoors status) by delegating to the appropriate `GridMap` or VMap/MMAP managers.
3.  **`TerrainManager`**: A singleton global registry that holds `TerrainInfo` instances for all loaded maps. It manages the lifecycle of entire maps and provides global accessors for terrain queries.

This unit does not interact with database tables directly; all terrain data is sourced from pre-generated binary files on disk.

## Member-by-Member Behavior

### GridMap Class

The `GridMap` class handles the raw binary parsing and interpolation of terrain data for a single grid.

#### Construction and Lifecycle
*   **`GridMap` (ctor)**: Initializes member variables to default states. Sets height retrieval strategy to `getHeightFromFlat` (constant height) and clears pointers for area, height, and liquid data arrays.
*   **`~GridMap` (dtor)**: Calls `unloadData()` to release allocated memory for terrain arrays.
*   **`loadData`**: Parses a binary `.map` file. It validates the file magic (`MAPS`) and version (`z1.4`). If valid, it sequentially loads area, holes, height, and liquid data sections based on offsets in the file header. It logs errors via `Log.Main/Out` if any section fails to load or if the file format is incompatible.
*   **`unloadData`**: Frees all dynamically allocated arrays (`m_area_map`, `m_V9`, `m_V8`, `m_liquidEntry`, etc.) and resets the height retrieval strategy to flat.

#### Data Loading Helpers
These private methods parse specific sections of the `.map` file:
*   **`loadAreaData`**: Reads the area flag header and the 16x16 grid of area IDs.
*   **`loadHeightData`**: Reads the height header. Depending on flags (`MAP_HEIGHT_AS_INT16`, `MAP_HEIGHT_AS_INT8`, or float), it allocates and reads the corresponding height map arrays (`m_uint16_V9/V8`, `m_uint8_V9/V8`, or `m_V9/V8`). It sets the function pointer `m_gridGetHeight` to the appropriate interpolation method (`getHeightFromUint16`, `getHeightFromUint8`, or `getHeightFromFloat`). If no height data is present, it defaults to `getHeightFromFlat`.
*   **`loadHolesData`**: Reads the 16x16 array of hole flags, which indicate invalid terrain areas (e.g., gaps in the mesh).
*   **`loadGridMapLiquidData`**: Reads liquid headers and arrays for liquid type, flags, and height levels.

#### Terrain Querying
*   **`getHeight`**: An inline method that invokes the current `m_gridGetHeight` function pointer. This allows polymorphic behavior based on how the height data was encoded in the file.
*   **`getHeightFromFlat`**: Returns the constant `m_gridHeight` value. Used when no detailed height map is available.
*   **`getHeightFromFloat`**, **`getHeightFromUint8`**, **`getHeightFromUint16`**: These methods perform bilinear interpolation on the height map. They convert world coordinates to grid-local indices, check if the point is in a "hole" (invalid terrain), and then calculate the height using linear equations derived from the surrounding vertices (h1-h5) in the height map triangles. The integer versions apply a multiplier and base height offset.
*   **`getArea`**: Converts world coordinates to the 16x16 area grid index and returns the area ID. If no area map is loaded, it returns the global grid area.
*   **`getLiquidLevel`**: Interpolates the liquid height at the given coordinates from the `m_liquid_map` array.
*   **`getTerrainType`**: Returns the liquid terrain type flag for the cell containing the coordinates.
*   **`getLiquidStatus`**: Determines the relationship between the entity's Z coordinate and the liquid/ground levels. It checks liquid type entries via `TerrainManager/GetLiquidType` and `AreaEntry/GetById` to resolve liquid overrides. It compares the liquid level against the ground level (obtained via `getHeight`) and the entity's Z to return a status: `LIQUID_MAP_UNDER_WATER`, `LIQUID_MAP_IN_WATER`, `LIQUID_MAP_WATER_WALK`, `LIQUID_MAP_ABOVE_WATER`, or `LIQUID_MAP_NO_WATER`.

#### Static Utilities
*   **`ExistMap`**: Checks if a `.map` file exists on disk and validates its header magic/version. Logs errors via `Log.Main/Out` and uses `World/GetDataPath` to construct the file path.
*   **`ExistVMap`**: Checks if a VMap file exists for the grid. It delegates to `IVMapManager/existsMap` and `IVMapManager/getDirFileName`. It logs errors if the file is missing or if VMap loading is disabled.

### TerrainInfo Class

`TerrainInfo` manages the collection of `GridMap` objects for a single map ID. It implements lazy loading and reference-counted caching.

#### Construction and Lifecycle
*   **`TerrainInfo` (ctor)**: Initializes the 32x32 grid matrices to null/zero. Sets up a timer (`ShortIntervalTimer`) for periodic garbage collection of unused grids, with a randomized start delay to prevent thundering herds.
*   **`~TerrainInfo`**: Deletes all `GridMap` objects in the matrix. Unloads the map from VMap and MMap managers via `VMapFactory/createOrGetVMapManager` and `MoveMap/createOrGetMMapManager`.
*   **`LoadAll`**: Iterates through all 32x32 grids and forces loading of each via `Load`. Called during map initialization.
*   **`CleanUpGrids`**: Called periodically via `TerrainManager/Update`. It checks the reference count (`m_GridRef`) for each grid. If a grid is loaded but has zero references, it unloads the `GridMap` data, deletes the object, and unloads the corresponding VMap/MMAP data.

#### Grid Management
*   **`Load`**: Retrieves or creates a `GridMap` for the specified grid coordinates. It first increments the reference count via `RefGrid`. If the grid is not already loaded, it calls `LoadMapAndVMap` to load the binary data and associated VMap/MMAP data.
*   **`Unload`**: Decrements the reference count via `UnrefGrid`. It does not immediately delete the grid; deletion is deferred to `CleanUpGrids` to allow for safe concurrent access and batched cleanup.
*   **`RefGrid`** / **`UnrefGrid`**: Thread-safe increment/decrement of the grid reference counter using `m_refMutex`. Throws exceptions via `Errors/PrintStacktraceAndThrow` if assertions fail (though the code shown uses `MANGOS_ASSERT`).
*   **`GetGrid`**: A helper that calculates the grid coordinates from world X/Y and returns the `GridMap` pointer, triggering a load if necessary. Note: The comment indicates the X/Y calculation is reversed relative to standard expectations ("Giperion Elysium: It's reversed. That's ok").
*   **`LoadMapAndVMap`**: The core loading routine. It uses a double-checked locking pattern with `m_mutex` to ensure thread safety. It constructs the file path using `World/GetDataPath`, loads the `GridMap` data, and then loads the corresponding VMap and MMap data via `VMapFactory` and `MoveMap` factories.

#### Terrain Queries
`TerrainInfo` methods typically delegate to the underlying `GridMap` or VMap/MMAP managers, often combining results for accuracy.

*   **`GetHeightStatic`**: Calculates the ground height at a point. It first queries the `GridMap` height. If VMaps are enabled (`IVMapManager/isHeightCalcEnabled`), it queries the VMap height starting from slightly above the entity's Z. It employs a complex fallback strategy: if VMap height is not found, it searches wider ranges or looks upwards/downwards relative to the map height. It returns the most appropriate height (usually VMap if indoors, Map if outdoors or if VMap is unreliable).
*   **`IsOutdoors`**: Determines if a point is outdoors. It calls `GetAreaInfo` to check for WMO (World Model Object) data. If no WMO is found, it assumes outdoors. Otherwise, it checks the `mogpFlags` using the `IsOutdoorWMO` helper.
*   **`GetAreaInfo`**: Queries VMap for area information (flags, ADT ID, root/group IDs). It verifies that the terrain height doesn't contradict the VMap result (i.e., ensures the player isn't underground relative to the map height).
*   **`GetAreaFlag`**: Retrieves the area flag for a point. It prefers WMO area data if available (via `GetAreaInfo` and `DBCStores/GetWMOAreaTableEntryByTripple`), otherwise falls back to the `GridMap` area data or a default map flag.
*   **`GetTerrainType`**: Delegates to `GridMap::getTerrainType`.
*   **`GetAreaId`**, **`GetZoneId`**, **`GetZoneAndAreaId`**: Convert area flags to Area/Zone IDs using `TerrainManager` static helpers.
*   **`getLiquidStatus`**: Similar to `GridMap::getLiquidStatus` but integrates VMap liquid data. It first tries VMap (`IVMapManager/GetLiquidLevel`). If VMap finds water, it resolves liquid types and overrides via `AreaEntry`. If VMap fails or finds no water, it falls back to `GridMap::getLiquidStatus`.
*   **`IsSwimmable`**: Checks if a unit can swim at a location. It requires the unit to be in water (or able to jump into it) and verifies there is sufficient depth (`radius`) between the water surface and the ground.
*   **`IsInWater`** / **`IsUnderWater`**: Boolean checks for water immersion, delegating to `getLiquidStatus`.
*   **`GetWaterOrGroundLevel`**: Returns the higher of the water level or ground level. Useful for positioning entities on the surface. It accepts a `swim` flag to adjust the returned Z for underwater positioning.
*   **`GetWaterLevel`**: Specifically returns the water level height, using VMap or GridMap data.

### TerrainManager Class

A singleton that manages `TerrainInfo` instances globally.

*   **`TerrainManager` (ctor)**: Initializes the `mLiquidTypes` vector with hardcoded `LiquidTypeEntry` objects for common liquid types (water, ocean, etc.).
*   **`~TerrainManager`**: Deletes all `TerrainInfo` objects in the `i_TerrainMap`.
*   **`LoadTerrain`**: Retrieves or creates a `TerrainInfo` instance for a given map ID. Thread-safe via `Guard`.
*   **`UnloadTerrain`**: Removes a `TerrainInfo` instance if it is not referenced. Checks `World/getConfig` for `CONFIG_BOOL_GRID_UNLOAD` to respect server settings.
*   **`Update`**: Called by `World/Update`. Iterates through all `TerrainInfo` instances and calls `CleanUpGrids` to perform garbage collection.
*   **`UnloadAll`**: Deletes all `TerrainInfo` instances and clears the map.
*   **`GetAreaIdByAreaFlag`**, **`GetZoneIdByAreaFlag`**, **`GetZoneAndAreaIdByAreaFlag`**: Static helpers that convert area flags to IDs using `AreaEntry/GetByAreaFlagAndMap` and `AreaEntry/IsZone`.

## Data Model

This unit does not interact with database tables. All terrain data is stored in binary `.map`, `.vmap`, and `.mmap` files on disk.

## Notable Implementation Details

*   **Height Interpolation**: `GridMap` supports three different height map encodings (float, uint8, uint16) to optimize memory usage. The `m_gridGetHeight` function pointer allows runtime selection of the appropriate interpolation algorithm.
*   **Lazy Loading**: `TerrainInfo` uses lazy loading for grids. Grids are only loaded when first accessed via `GetGrid` or `Load`. This reduces initial memory footprint and startup time.
*   **Reference Counting**: `TerrainInfo` uses reference counting (`m_GridRef`) to manage grid lifetimes. Grids are not deleted immediately when unloaded; instead, they are marked for deletion and cleaned up in batches by `CleanUpGrids`. This prevents frequent allocation/deallocation overhead and allows for safe concurrent access.
*   **VMap Integration**: `TerrainInfo` heavily integrates with VMap for indoor height and area queries. `GetHeightStatic` has a complex fallback strategy to handle cases where VMap data is missing or inconsistent with Map data.
*   **Liquid Overrides**: Liquid types can be overridden by area data. Both `GridMap::getLiquidStatus` and `TerrainInfo::getLiquidStatus` check `AreaEntry` for `LiquidTypeId` overrides, ensuring that specific zones can define custom liquid behaviors.
*   **Thread Safety**: `TerrainInfo` uses mutexes (`m_mutex`, `m_refMutex`) to protect grid loading and reference counting. `TerrainManager` uses a class-level lock for its singleton instance.
*   **Garbage Collection**: `TerrainManager::Update` triggers periodic garbage collection of unused grids via `TerrainInfo::CleanUpGrids`. This helps manage memory usage on long-running servers.
*   **Coordinate Reversal**: `TerrainInfo::GetGrid` contains a comment indicating that the X/Y calculation for grid coordinates is reversed. This is a known quirk that must be accounted for when debugging terrain issues.
